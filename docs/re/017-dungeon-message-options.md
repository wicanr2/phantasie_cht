## 正常玩家路線與正式收據

公開路線：[dungeon-options.route](../../tests/routes/dungeon-options.route)，32 個檢查點。沿既有地牢前段到 `(16,9)`，再走到 `(14,12)`。離開選項後退一步並重訪，接著選擇拉動，確認後進入原版戰鬥。全程是正常按鍵，沒有位置、物品或種子注入。DOS `AH=2Ch` 沿既有固定零時刻；四語與各模式使用同一初始輸入及讀鍵路徑。

正式收據在 `workplace/explore-dungeon/ab-dungeon-options/`；工具為同目錄上層的 `verify_options.py`。四語 × none/off/on/on-f2，共 512 點：384 個覆繪 UI PASS，128 個 none UI SKIP 只作原版狀態基準。

- 每點 steps、reads、VRAM、映像範圍及完整 1 MiB 記憶體雜湊跨模式、語言相同。20,000 與 40,000 步取樣的 Layer 雜湊相同。
- 所有期望鍵存在，位置、殘字、外露及遮罩稽核為零。離開與後續戰鬥畫面沒有訊息或選項的疊字。
- `options_visual.go` 由 catalog、字型寬度與原版色號分布獨立核對全文、補白、前景與背景，不以 `layoutLine` 或 `recolor` 的輸出作期望。四語初始選項、反白往返、重訪、後續兩行及戰鬥選單均通過，原生及兩倍像素差異限原始文字矩形，沒有缺字。
- `-fault noadd` 使目標 `lever-options` 有 4 個外露事件、缺少三個期望鍵並 FAIL。另在忽略副本恰好刪除一列選項 prose，目標因比對鍵缺少而 FAIL；該例可退回 UI catalog，不能宣稱整列英文外露。

## 調色盤觀察

唯讀探針在 dosgolem `img:4E60` 讀 INT 10h 引數，在 `img:4EE0` 讀完成後狀態。7,707,757 步時 `AX=0B00h`、`BX=0100h`，即 `BH=1`、`BL=0`。CGA 色盤由黑、淺青、淺洋紅、白改為黑、淺綠、淺紅、黃；VRAM 位元組未變。原始收據為 `options-palette.jsonl`。切換後四語戰鬥選單的顏色與像素範圍已獨立核對。

這個樣本沒有證明 `BL=1` 或原有文字跨調色盤切換的失效處理。規格 002 的其餘未量到分支保持 READY。

## 限制與證據清冊

- 已驗證長 40、兩個 11 字元選項，以及動作後長 80 的無選項段落。MESS5 索引 61 短訊息另見 [018](018-short-message-reachability.md)、[009](../spec/009-short-message-catalog.md)；其他短訊息、較多選項及 3 字元欄位尚未動態驗收，規格 005 保持 READY。
- 初次東側候選路線遇到戰鬥或其他提示，未到達目標，不作完成證據。沿已驗收前段的西側路線才是正式基準。
- 初次生成後續期望時誤把動作 10 當成訊息 10，原始資料及 IDA 消費端核對後改用訊息 68。沒有因此改引擎或資料。
- 拉動後的原版戰鬥曾被錯當成返回地圖，已依原版 bytes、正常座標與畫面修正期望；失敗收據保留在忽略目錄。

完整工具、路線、二進位、catalog、字型及正式收據雜湊在 `workplace/explore-dungeon/options-verification-manifest.json`。原版與本機探索影像不加入版控。
