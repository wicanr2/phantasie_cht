## 正常路線

從原版啟動鏈建立四人隊伍，正常進 DNG1 `(20,7)` 的戰鬥。保留每個實際按鍵與停點，經原版速度選單切到快，再沿原版戰鬥指令進行。沒有物品授予、位置注入、改存檔、跳題、強制勝利或重新擲骰。使用 dosgolem 既有固定 DOS 時鐘及相同初始輸入。

| 停點 | 步數 | 讀鍵數 | 原版狀態 |
|---|---:|---:|---|
| 勝利標題 | 1051699527 | 129669 | state 12，確認等鍵 |
| 生還者獎勵 | 1051795638 | 129670 | state 12，確認等鍵 |
| 確認後返回 | 1051796963 | 129671 | state 3，DNG1 `(20,7)` |

每個結算停點以零步快照切到其餘三語、英文及回切 zh-TW。這是四語切換驗收，不宣稱四種初始語言各自重跑長路線。本機路線與影像不進版控。

## 顯示核對與取樣診斷

`victory_visual.go` 用字面期望、ASCII／全形寬度及上述原版矩形核對三列全文、數值、補白、Shown 狀態與原版色號導出的顏色，不呼叫 Resolver、FormatTarget 或 layoutLine 產生期望值。兩種倍率的差異只在批准矩形內，沒有缺字。英文視圖等於原版，回切 zh-TW 恢復相同像素；正常返回後結算鍵及視窗內疊字清除。

三列依既有 001 §6、003 §8 靠左補白。獎勵模板的置中標記位於內層 Piece，既有契約不向外傳遞。初次核對器錯把三列當成置中，已修正期望值；未因此修改顯示程式或 TSV。

初次探索路線漏列既有選單分隔線的 `@known-untranslated`，正式核對已補上相同基線註記。兩份路線的按鍵、取樣步數及語言動作相同；初次失敗收據保留作診斷。

初次 `round8` 在 168251608 步，PC 為 `21AF:4EA2`，原版 BIOS 包裝仍在途。20,000 步取樣已有 Shown 疊字，40,000 步取樣則仍是 Pending。只讀探針量到 34 步後，PC 為 `21AF:3993`，`Hooks.Busy()` 變為假。

公開 `combat` 路線與本機路線均將 `round8` 延後 34 步，`round9` 扣回 34 步。兩個快照間沒有玩家輸入，累計步數從 `round9` 起保持原樣。乾淨重跑四模式後，每點圖層摘要一致；除延後的 `round8` 外，所有原版狀態也與修正前逐點相同。此處只修正擷取時機，未修改原版或疊字忙碌閘門。

## 正式驗收

| 閘門 | 結果 |
|---|---|
| none、off、on、on-f2，各 129 點 | 516 個原版狀態相同；steps、reads、VRAM、映像範圍、完整 1 MiB 及存檔欄位逐點一致 |

| 20,000 與 40,000 步取樣 | 每點 Layer 雜湊相同；修正後 `round8` 的 PNG 亦相同 |
| 全文、數值及像素 | 四語及回切繁中、兩種倍率共 20 項；三列全文、Shown、補白、顏色與批准矩形均通過 |
| 英文、回切及返回 | 兩個英文畫面等於原版，兩次繁中回切恢復相同像素；正常確認後結算鍵與視窗疊字清除 |
| 負對照 | 本機副本恰好刪掉一列獎勵模板，其餘 TSV 位元組相同；獨立核對以缺少可見獎勵列失敗 |

所有正向停點的位置、殘字、外露及遮罩稽核為零。原始 70 個檔案雜湊不變，catalog、字型及程式亦未改。公開路線只改上述兩個取樣數字，其餘 22 條路線不變。

正常返回的 `op_load2` 從 0 增至 1，`shadow_restore` 從 30 增至 31，對應常駐映像 `0D10` 至 `0D2F`。等級為已證實，限操作觀察；第二頁影子的獨立還原與負對照仍未驗收，見 [002 §12](../spec/002-screen-op-invalidation.md#12-勝利後第二頁還原的觀察)。

本節只證明這場正常勝利的三列文字、四語切換及返回。全滅與其餘未量到分支仍待處理，005 維持 READY。不可變鍵為 `dosgolem／常駐映像 2EA0、2EEE、2F10／OV2 靜態引數及 DGROUP:638E`。001、003 的既有契約與 RE008 均已回填本檔入口，005 §9.2 與 §17 將勝利從未量到改為本場景已驗收。
