# 004 overlay 格式與載入語意

日期：2026-10-03。範圍：`OV1.OVR`、`OV2.OVR` 的檔案格式、常駐載入器 `sub_4E1C`（`0110:3D1C`）的語意，以及兩個 overlay 的靜態盤點。
全部是靜態證據（檔案 bytes 與常駐映像的反組譯），尚未有動態量測；動態量測依賴 `INT 27h`（Issue #1、#2）。
證據等級：已證實、強推論、假說、未知。

## 檔案格式

| 項目 | 內容 | 等級 |
|---|---|---|
| 標頭 | 14 bytes = 7 個小端字組：簽章、程式碼目的偏移、程式碼長度、資料目的偏移、資料長度、額外長度、入口偏移 | 已證實（載入器讀 `0Eh` bytes 後逐欄使用） |
| 本體 | 標頭之後依序是程式碼段落（長度 = 程式碼長度）、資料段落（長度 = 資料長度） | 已證實（兩個檔案的 `14 + 程式碼長度 + 資料長度` 都等於檔案大小） |

| 欄位 | `OV1.OVR` | `OV2.OVR` |
|---|---|---|
| 檔案大小 | 25,703 | 32,963 |
| 簽章（+0） | `00F2h` | `00F2h` |
| 程式碼目的偏移（+2） | `53EAh` | `53EAh` |
| 程式碼長度（+4） | `58EBh`（22,763） | `75A5h`（30,117） |
| 資料目的偏移（+6） | `B8F0h` | `B8F0h` |
| 資料長度（+8） | `0B6Eh`（2,926） | `0B10h`（2,832） |
| 額外長度（+10） | `001Ch`（28） | `0EC6h`（3,782） |
| 入口偏移（+12） | `A591h` | `C8CFh` |

「額外長度」只在載入器的大小檢查中使用（見下），用途未驗證。兩個程式碼段落的第一個位元組是 `55 8B EC`（`push bp; mov bp,sp`），入口落在各自程式碼範圍內。

## 載入器語意（`0110:3D0F` `sub_4E0F` 與 `0110:3D1C` `sub_4E1C`）

| 步驟 | 內容 | 等級 |
|---|---|---|
| 1 | `sub_4E0F(名稱指標)` 把參數存入 `DGROUP:3A88`（IDA 名稱 `word_11578`），呼叫 `sub_4E1C`，以其回傳值 `jmp ax` | 已證實 |
| 2 | 組出檔名：以兩個字串函式（`sub_5F26`、`sub_5EEF`，內容未讀）處理名稱指標與 `DGROUP:3096` 的字串 `.ovr`；名稱指標 `0Bh`、`0Fh`、`13h`、`17h` 分別指向 `DGROUP` 內的 `ov1`、`ov2`、`ov1`、`ov2` | 檔名組成為強推論；指標對應字串已證實 |
| 3 | 開檔（`sub_5D03`），失敗回 `FFFFh` 時以錯誤碼 `0Ah` 呼叫 `sub_4F00` | 已證實 |
| 4 | 讀 14 bytes 標頭（`sub_6249`），不足以錯誤碼 `14h` 結束；第一個字不是 `00F2h` 以 `1Eh` 結束 | 已證實 |
| 5 | 檢查 `資料目的偏移 + 資料長度 + 額外長度` 不超過 `DGROUP:320A` 處的變數（IDA 名稱 `word_10CFA`，值未知），否則錯誤碼 `28h` | 已證實 |
| 6 | 檢查程式碼目的偏移不小於 `53EAh`、資料目的偏移不小於 `B8F0h`，否則錯誤碼 `3Ch` | 已證實 |
| 7 | **程式碼段落讀到 `CS:程式碼目的偏移`**：`sub_5CCC` 在呼叫 `AH=3Fh` 前設 `DS=CS`（`0110:4BD9` 的 `mov ax,cs; mov ds,ax`）。讀到的位元組數小於程式碼長度時錯誤碼 `32h` | 已證實 |
| 8 | **資料段落讀到 `DS:資料目的偏移`**（`sub_6249`，DS 為 DGROUP）。位元組數小於資料長度時錯誤碼 `32h` | 已證實 |
| 9 | 關檔，回傳入口偏移（標頭 +12），由 `sub_4E0F` 以 `jmp ax` 近跳到 `CS:入口偏移` | 已證實 |
| 錯誤 | `sub_4F00(碼)` 以格式字串（含 `%d`，`DGROUP:309B`）組出訊息，寫出後以離開碼 `64h` 結束程式 | 已證實 |

載入器**每次被呼叫都重新開檔、重新載入**，沒有「已載入」的快取檢查（反組譯內沒有這類比較）。

### 位址模型

| 項目 | 值 | 等級 |
|---|---|---|
| 程式碼位址 | `CS=0110`，偏移 `53EAh` 至 `ACD5h`（`OV1`）或 `C98Fh`（`OV2`）。兩個 overlay 的程式碼範圍起點相同，互相覆蓋 | 已證實（標頭） |
| 資料位址 | `DS=0DAF`，偏移 `B8F0h` 起，`OV1` 到 `C45Eh`、`OV2` 到 `C400h`。兩者互相覆蓋 | 已證實（標頭） |
| IDA／映像線性位址 | 程式碼 `0110:53EA` = 線性 `64EA`；資料 `DGROUP:B8F0` = 線性 `193E0` | 算術 |
| 與常駐映像的關係 | 載入位置在常駐程式碼段內（`0110:53EA` 以後直到 DGROUP 起點 `0110:C9F0`）與 DGROUP 上端。overlay 以近呼叫（`E8`）直接呼叫常駐函式，不經載入器 | 強推論（overlay 內的呼叫目標都落在常駐位址，見盤點） |
| 目前載入的是哪一個 | 位址相同，不能以 CS:IP 區分。可用的區分來源：載入器最後一次開的檔名（`AH=3Dh` 的路徑含 `ov1` 或 `ov2`），或 `DGROUP:3A88` 的名稱指標（`0Bh`、`13h` 為 `ov1`；`0Fh`、`17h` 為 `ov2`） | 強推論（載入器每次重新載入、載入失敗即結束程式） |

這解決 `AGENTS.md` §2 未知項 5 的前半：段位址不隨狀態變動，是固定的 `0110`；overlay 的穩定鍵由「`ov1` 或 `ov2`」加「`0110` 內偏移」組成。後半（載入時機、呼叫頻率）需要動態量測。

## 靜態盤點

方法：`tools/ida/compose_overlay.py` 依載入器語意把 overlay 疊在常駐映像上，`tools/ida/ida.sh overlay ov1|ov2` 建庫；種子為入口偏移、程式碼段落起點與段落內的 `55 8B EC`、`55 89 E5`。DS、SS 預設為 `0DAF`。輸入雜湊（疊合後映像，不進版控）：

| 映像 | SHA-256 |
|---|---|
| `ov1_composed.bin` | `a2f1e2160e030d5688d8d41cb07177b92c4fba00fa8338c87458f9210709fa6f` |
| `ov2_composed.bin` | `f461da5fb4e02634ab47dcbd8af3f5b7ae53c49d00ad42f5f56fcae765121422` |

| 項目 | `OV1` | `OV2` | 等級 |
|---|---|---|---|
| 範圍內函式數 | 112 | 119 | 已證實（IDA 輸出；序言種子為啟發式） |
| IDA 函式範圍涵蓋的 bytes | 19,112 / 22,763 | 30,117 / 30,117 | 已證實；函式範圍可能含資料，不等於全是指令 |
| 範圍內的 `INT` 與 `int86` 呼叫點 | 0 | 0 | 已證實（已分析範圍內） |
| 範圍內的 `B800h`、`A000h` 等視訊段常數 | 0 | 0 | 已證實（已分析範圍內） |
| 範圍內的 `in`／`out` | 1（`in ax,26h`，疑為誤解碼的資料） | 0 | 已證實；語意未驗證 |
| 資料段落內的字串（IDA 清單，最短 5 字元） | 142 | 132 | 已證實 |

資料段落的字串是 `printf` 風格的格式字串與訊息：`OV1` 含結局與任務敘述、狀態訊息（含 `%s` 格式）、檔名 `ibmcover`；`OV2` 含戰鬥與法術訊息（含 `%s` 格式）。本文不收錄原文。

### 結論與限制

- overlay 不直接做 `INT`、不寫視訊記憶體、不操作連接埠，輸入輸出都經常駐函式。繪字路徑因此在常駐程式碼，見 `005-video-and-text-paths.md`。
- 玩家可見字串分布在三處：常駐 `DGROUP`（選單詞、名稱、物品名等，見 `003`）、`OV1` 的資料段落、`OV2` 的資料段落。`MESS1` 至 `MESS10`、`SCROLLS.DTX` 的讀取者仍未知（Issue #4）。
- 覆蓋率以函式範圍計，沒有逐指令核對；結論只涵蓋已分析範圍。
- 疊合映像假設載入器的語意如上。動態量測（Issue #2）要核對：實際載入位址、載入頻率、`word_10CFA` 的值。
