## 九選項的正常路線

等級：已證實，限本條正常玩家路線。沿 [020](020-combat-death-messages.md) 的正常戰鬥前綴，兩名隊員存活。經原版求饒及金幣結算返回地牢，再以方向鍵走至神殿。沒有授予物品、改存檔、位置注入、強制結果或重新擲骰。既有手冊作答輸入只由本機已記錄路線重播，路線不進版控。

第一個視窗依序向下、向上、確認，再返回地牢。第二個視窗由第一列向下走遍其餘八列，再確認原版選項，接續法術、死亡報告及全滅。此處只驗證選項移動與原版結果，不推導謎題解法。

兩組數字原文的空白位置不同。引擎依 003 §5 將純數字事件直接保留，沒有數字疊字。獨立核對器直接讀原版 `FONT` 的 2-bit 像素遮罩，核對九個三字元矩形、原版反白及色號。四語切換後數字像素仍等於原版，正文與位置列的覆繪不進入選項矩形。

## 九選項與神殿的驗收

| 閘門 | 結果 |
|---|---|
| none、off、on、on-f2，各 337 點 | 1348 個原版狀態相同；步數、讀鍵、VRAM、映像範圍、完整 1 MiB 及存檔欄位逐點一致 |
| 88 個目標停點 | 三個有鉤子模式共 264 個 UI PASS；none 只作原版基準 |
| 兩種 Frame 節奏 | 每點 Layer 雜湊相同 |
| 獨立全文與像素 | 146 項四語、回切及兩種倍率檢查；全文、補白、Shown、顏色及批准矩形通過 |
| 數字選項 | 56 項原版字模、反白與像素保留檢查，各含九個選項 |
| 切換與返回 | 13 個英文畫面等於原版，13 次回切恢復同圖；第一個視窗返回與全滅返回均清除舊覆繪 |
| 負對照 | 副本恰好刪除第二視窗的一列正文，其餘 TSV 位元組相同；獨立核對以缺少可見正文失敗 |

`nine_visual.go` 的期望為獨立字面譯文、ASCII／全形寬度及原版矩形，不呼叫 Resolver、FormatTarget 或排版函式。畫面差異只在批准範圍，沒有缺字；Frame 及切換前後完整記憶體雜湊不變。

長前綴的 102 個無文字旅行停點只作原版狀態診斷，on 與 on-f2 的「疊字數為 0」不算 UI PASS。四語由正常場景零步切換驗收，不宣稱四種初始語言各自重跑長路線。其餘短訊息、事件型別及未量到分支仍保留，005 維持 READY。
