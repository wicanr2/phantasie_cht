# 011 地城位置列的格式字串指標（OV2:C400）

日期：2026-10-04。目的：查地城畫面底部位置列（例如 `--- AN OLD CRUMBLING STONE HALLWAY ---`）為何沒有被覆繪。該行文字在 MESS1，譯文也在 `text/prose.zh-TW.tsv`，但事件的格式字串指標不在任何已知區間，被判成 `other`，不查 catalog。

## 證據

| 項目 | 內容 | 等級 |
|---|---|---|
| 事件 | 地城內位置列的 `25A5` 呼叫端是 OV2 的 `811B`，格式字串指標（`25A5` 的 `[BP+8]`）恆為 `C400`。同一路線內出現四種位置列文字，指標都是 `C400`。收據的診斷鍵集合 `fmt_other_ptr` 記為 `811B/C400/<摘要>` | 已證實（動態，`-dump-keys`） |
| 內容 | 其中一筆的文字摘要 `h:9d0421748f99` 與 MESS1 第 15 筆訊息（40 bytes）的 prose 鍵相同。其他三筆的摘要也是 MESS 訊息行 | 已證實（一筆）／強推論（其餘三筆） |
| 區間 | `C400` 是 OV2 資料區的界外起點（`docs/re/004`：OV2 資料到 `C400`），在 OV1 下 `C400` 仍屬 OV1 靜態資料區（到 `C45E`）。所以 `C400` 起的訊息行緩衝區只在載入 OV2 時成立 | 已證實（OVR 標頭與動態） |
| 大小 | 訊息行最多 40 個可印字元（MESS 訊息記錄長度 40）。區間取 `C400` 起 80 bytes（與行緩衝區 `638E` 同大小），實測只見起點 `C400` | 強推論 |

## 處理

- 區間表 `apps/phantasie/regions.tsv` 加一列 `buffer@ov2 C400 0 50`：`C400` 起 80 bytes 在載入 OV2 時歸 `buffer` 種類，查 `prose`。
- 收據工具加 `-dump-keys` 旗標與診斷鍵集合 `fmt_other_ptr`（呼叫端、格式字串指標、文字摘要），用來找「文字在 catalog 內卻沒被覆繪」的指標落點。
- 驗證：`tests/routes/` 的地城路線（探索代理的 `dg2.route`）在 `w21` 檢查點，位置列顯示 `--- 老舊崩塌的石造走廊 ---`。
