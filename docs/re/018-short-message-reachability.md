### 漏譯原因與驗收限制

實作前的 `tools/prose_export.py` 明確略過 `kind == "short"`。`MESS5` 索引 61 已被 `gamedata.py` 正確列為短訊息，但沒有進入翻譯單位及正式正文 catalog。兩個選項鍵與其他訊息共用，已有譯文。缺口已依 009 修正：以 `--include-short mess5:61` 明示納入實測正文，四語各新增一列；未指定的短訊息仍略過。

本機 `short-pilot/` 有 156 個診斷停點。無文字地圖停點被收據工具標為「疊字數為 0」，本批不宣稱整條 UI 驗收通過。八個 `short-*` 停點的既有工具 verdict 為 PASS，但正文鍵沒有出現在可見鍵集合；這只能證明已有選項等疊字，不能證明短訊息已中文化。正式驗收必須明示三個必備鍵，另核對全文、安全矩形、顏色及原版狀態。

`short_visual.go` 是本機獨立核對器，要求三個實際記錄及全文。補譯前與補譯後只刪除新正文列的副本都因記錄不足失敗，證明它能抓出上述缺口。引擎未改；正式四語字型已重建，新增字元本來就在子集內，所以二進位雜湊不變。

## 四語驗收

等級：已證實，限上述八個短訊息停點。

- `workplace/explore-dungeon/ab-dungeon-short-v2/` 的四語 none/off/on/on-f2，共 2496 個原版狀態點相同。八個短訊息停點在 off/on/on-f2 共 96 個 UI PASS；none 的 32 點僅作原版基準。兩種取樣節奏的四語 Layer 相同。
- 五個選項停點包含正文與兩個選項的三個必備鍵。返回、移動與開啟結果三鍵消失；開啟結果維持原版物品保留提示。
- `short-visual-all.log` 的四語五個選項停點，原生及兩倍共 40 項通過。全文、置中補白、原版色號及安全範圍由獨立核對器確認。負對照在 `short-visual-negative.log`。
- 私有路線中的 85 個無文字旅行點只作狀態診斷，不算 UI PASS。none 不產生 `image_hash`；只核對其實際提供的原版狀態欄位。完整範圍、工具處置及清冊入口見 009。
