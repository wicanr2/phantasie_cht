# 006 動態證據（`INT 27h` 補上之後）

日期：2026-10-03。dosgolem 分支 `phantasie-cht-overlay`（基底 `origin/buck-rogers-cht-output-overlay`，加 `INT 27h` 的規格與實作）。
工具：`cmd/probe`、`apps/phantasie/cmd/textlog`（唯讀，hook 只讀記憶體）。證據等級：已證實、強推論、假說、未知。
前一份動態收據是 `002`（串跑不等價）；本份是補上 `INT 27h` 之後的第一批可信量測。

## 啟動鏈

| 項目 | 結果 | 等級 |
|---|---|---|
| 批次檔解析 | 啟動鏈取自使用者目錄內唯一的批次檔，依序為三個 `.COM`、主程式 | 已證實 |
| 各程式 PSP | `0100`、`1101`、`1950`、`219F`；主程式映像段 `21AF`，DGROUP `2E4E`（`21AF + 0C9Fh`） | 已證實 |
| 向量 60h 至 63h | 60h `49A6:49A6`；61h、62h、63h 為 `0100:0000`、`1101:0000`、`1950:0000`；每個位元組只被寫一次 | 已證實（`-watch 180-18F`） |
| 視訊模式 | 04h，主程式第 267,502 道指令附近切換 | 已證實 |
| 啟動讀檔 | 字模檔讀入 `DGROUP:3244`（2,032 bytes）；封面圖讀入 INT 61h 緩衝區（5,273 bytes，目的 `0100:0000`） | 已證實 |

## 鍵盤路徑

| 觀察 | 說明 | 等級 |
|---|---|---|
| 遊戲在等鍵時忙等：`INT 16h AH=01` 與 `AH=00` 各被呼叫上萬次 | dosgolem 的 `INT 16h AH=00` 在佇列空時不阻塞、直接回 0（`internal/dos/bios.go`），遊戲把回傳 0 當成無效鍵再迴圈 | 已證實 |
| 外部在任意步數放進 BIOS 佇列的鍵被丟棄 | 遊戲每次讀鍵之前先清空鍵盤緩衝（`0110:3933`：`AH=01`、`AH=00` 迴圈直到無鍵）。鍵在清空動作中被讀掉，讀鍵函式（`0110:37C2`）永遠等不到 | 已證實（路徑一：任意步數送鍵，畫面不變；路徑二：在讀鍵入口送鍵，選單移動） |
| 在讀鍵入口才放進佇列（`KeyGate`）時，上、下與 Enter 都正確運作 | 等價於真機上「按鍵發生在程式阻塞等待期間」 | 已證實 |

## 畫面與文字事件（標題、城鎮、公會選單）

| 項目 | 結果 | 等級 |
|---|---|---|
| 標題畫面 | 5 次繪字：4 行選單（呼叫端為常駐，格式字串 `%s`）、底部提示（呼叫端在 `ov1`，格式字串為字面文字） | 已證實 |
| 選單高亮 | 以反相函式（`0110:0672`）反相 `(列, 欄, 寬)`；移動選項時先反相舊的、再反相新的 | 已證實 |
| 城鎮畫面 | 頂端選單列 7 項與底部城名各一次繪字；底部城名後呼叫 `0110:372D`（存第 24 列到緩衝區 1） | 已證實 |
| 公會選單 | 先以 `0110:0D30` 存整頁、清視窗（BIOS 捲動）、以繪字函式逐格畫邊框（控制碼 04h 至 08h 當字模）、再畫項目文字 | 已證實 |
| 圖片來源 | 標題與城鎮的圖片是先載入緩衝區 1、再整頁還原到畫面（`0110:0CF0`），圖內的字屬圖面 | 已證實（寫視訊記憶體的呼叫端只有反相、整頁還原與繪字三類） |
| 視窗清除 | 視窗函式（`0110:0DAD`）以 `INT 10h AH=06` 清除一個字元格矩形，再畫框 | 已證實 |

文字事件在繪字函式的「格式化完成」位置（`0110:26E9`）取得，順序在原版取字模與寫視訊記憶體之前。
