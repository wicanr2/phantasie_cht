# 011 MESS 選項字元流解析

狀態：CONFORMED（2026-10-05，限資料列舉工具契約）。兩輪規格審查及實作複核的阻擋與應改皆為零。來源：[025](../re/025-option-stream-parsing.md)。前置：003、009 CONFORMED。本規格只修工具的資料列舉，不改引擎、正式 catalog 或原版規則。

## 契約

1. `parse_mess` 保留既有六欄回傳及 TSV 格式。正文、解碼、短訊息的 N=3、普通訊息的 N 判斷、11／3 欄寬及尾記錄規則不變。
2. 有效選項從正文開始索引與字元游標 L 接續讀取。以 `idx+floor(L/40)`、`L mod40` 為起點，取得 `(N-1)×欄寬` 個文字 bytes；每滿 40 個字元讀下一個現存 chunk，忽略該 chunk 的旗標。最後再切成 N-1 個完整欄位，保留頭尾空白與 NUL。
3. `used` 只新增實際有選項字元消費的索引。正文尾段與選項在同一 chunk 時不誤跳下一則訊息；選項跨記錄時不將已消費續段重新列為短訊息。最後一個字元恰在邊界時，不因原版預讀下一 chunk 而將其標為已消費。
4. 選項字元不足、遇到不存在索引或第 111 筆尾記錄時，以 `ValueError` 明確拒絕解析，不補出選項。既有 `chunk_at` 的檔尾填零不在本次重寫範圍；真實輸入的選項記錄須獨立核對皆完整位於來源檔內。本契約不承諾主程式跨檔寫入的原子性。
5. 不自動納入水池短訊息、不翻譯續段、不重建正式 catalog。修正後診斷匯出只留 workplace，缺譯清單供後續正常路線驗收。現有 009 的 MESS5:61 字元與選項必須相同。

## 驗收

- 合成輸入使用字面期望，核對正文後同 chunk 選項、正好 40 邊界、11 格字詞跨界、3 格跨界、尾空白及 NUL、後續旗標不參與文字、真正後一訊息保留、已消費續段不重列。
- 核對 N 的下限與上限、7／8 的欄寬分界、恰到 chunk 邊界、短訊息、缺記錄及尾記錄拒絕。期望不可由 `cells` 或新解析器自行計算。
- 唯讀原版的 55 個普通訊息選項單位，逐一以另一個獨立字元游標對照完整欄位、索引與原始 bytes；記錄 9 個訂正及新露出的真實訊息。其他既有列保持 byte 相同，MESS5:61 必須不變。
- 原版不存在時，原版核對明示 SKIP。原版匯出、全文、診斷譯文缺口與收據只留本機。
- 既有 prose 匯出、明示短訊息測試及正式 catalog 雜湊作最小回歸。此工具修正不支持新的 UI 完成聲明，002、005 仍 READY。
