## 3. 事件擷取

### 3.1 掛點與簽章檢查

全部唯讀，掛在最後一支載入的程式映像段 `img`（`PSP + 10h`，由 `ImageSeg` 取得）。安裝前逐一驗證位元組簽章，任一不符就停用疊字並印診斷（換版本或載入錯位時不得靜默失效）。簽章已對 `phantasi_unpacked.bin` 核對：

| 掛點 | 映像位移 | 時機 | 簽章（起始位元組） |
|---|---|---|---|
| A | `26E9` | 格式化與取字模完成，視訊寫入之前 | `8B 46 06` |
| B | `277D` | 共用結尾，視訊寫入已全部完成 | `8B C6 5E 5F` |
| L | `3D0F` | overlay 載入器入口，`[SP+2]` 是檔名指標 | `55 8B EC`（驗證時以實測位元組為準） |
| S | `3E35` | `sprintf(dest, fmt, ...)` 入口 | `55 8B EC` |
| `25A5` 入口 | `25A5` | 僅作簽章檢查 | `55 8B EC` |

此外 `002` 的掛點同樣要通過簽章檢查（入口 `55 8B EC`，完成位址 `C3`）。

### 3.2 冪等與配對

`RunUntil` 在指令前觸發 hook；時脈中斷可能在該指令之前送出，使同一位址的 hook 在同一次執行觸發兩次。所有成對 hook 以「開啟旗標加堆疊指標」去重：

- A 觸發：若已有開啟中的事件且 `SP` 相同，視為重入，忽略；`SP` 不同則上一個事件缺 B，計入 `unpaired` 後重新開始。
- B 觸發：只在有開啟中的事件時處理並關閉；沒有對應的 A 計入 `unpaired`。
- S、L 為單次通知，無去重需求，但同一 `Step` 與 `SP` 的重複通知忽略。

### 3.3 `EventRecord`

A 時擷取（唯讀記憶體），之後不再讀原版記憶體；語言切換與解析都只用 `EventRecord`。欄位：

| 欄位 | 內容 |
|---|---|
| `ID` | `g<N>`，遞增 |
| `Step`、`Caller`（`[BP+2]`）、`Overlay`（呼叫端位移 ≥ `53EA` 時 L 記錄的名稱，否則空） | |
| `Col`、`Row`、`Text` | `Text` 是 `DS:3A36` 的 NUL 結尾字串，取 `[:40]`；`len(Text)` 與 `DI` 相符時才記錄，不符計入 `badlen` |
| `FmtPtr`、`Format` | 格式字串最多讀 64 bytes；讀滿 64 bytes 仍無 NUL 計入 `truncated_input`，該事件不解析 |
| `Args` | `[BP+10]` 起 12 個字組 |
| `ArgStrs` | 對格式字串中每個 `%s` 轉換：引數指標、字串內容（最多 80 bytes，讀滿仍無 NUL 計入 `truncated_input`）、指標是否落在靜態字串區間（`003` §5） |
| `Composed` | 組句關聯（§3.4）：非空時含 `Fmt`、`Args`、`ArgStrs`（遞迴同結構，深度上限 3） |

格式字串的 `%` 解析規則在 `003` §7；解析失敗（未支援規格、尾端 `%`）時 `Format` 以字面看待並記 `badformat`。

### 3.4 組句關聯

S 掛點記錄最近 64 次 `sprintf`：`{dest, fmtptr, fmt, args(12 字組), strs}`，以 `dest` 為鍵只留最新一筆。A 時：

1. 若 `FmtPtr` 等於某筆記錄的 `dest`，且以「原版格式引擎的英文語意」（`003` §7.1）重新格式化該記錄的結果等於 `DS` 內 `FmtPtr` 處的目前字串，視為組句，`Composed` = 該記錄。
2. 對每個 `%s` 引數指標做同樣檢查（引數本身是組句緩衝區），成功就把該引數的 `Composed` 設為對應記錄。
3. 驗證失敗（緩衝區已被改寫、重用）則不關聯，事件走一般流程（字面鍵）。

計數：`composed`、`composed_miss`。

## 4. 事件分類

對有效文字 `t = Text[:40]`（`DI` 為準）：

| 類別 | 條件 | 處理 |
|---|---|---|
| E（空） | `len(t) = 0` | 忽略 |
| K（空白） | 全是空格 | 對事件矩形 `Layer.Clear`，不計缺譯 |
| N（非可列印） | 任一 byte 小於 `20h` 或大於 `7Eh` | 不翻譯；對事件矩形 `Layer.Clear`；記錄 byte 種類（`nonprintable`）。框線不覆繪 |
| T（文字） | 全部在 `20h` 至 `7Eh` 且含非空白字元 | 交給 `003` 解析 |

事件矩形：`x0 = Col × 8`、`y0 = Row × 8`、`x1 = min(x0 + len(t) × 8, 320)`、`y1 = min(y0 + 8, 200)`。`Col + len > 40` 或 `Row ≥ 25` 時裁切到畫布並計入 `clipped`（原版會寫進下一條掃描線，疊字層不跟隨）。

## 5. 解析介面

```go
// Resolve 是純函式：只讀 EventRecord 與 catalog，不碰原版記憶體。
func (c *Catalog) Resolve(rec *EventRecord, lang Lang) Result

type Result struct {
    Zh     []rune   // 譯文（尚未排版，可含 003 §8 的置中旗標資訊）
    Center bool
    Key    string   // 命中的 catalog 鍵，缺譯時是應補的鍵
    Missed []string // 查不到的靜態字串引數（資料型引數不列入）
    OK     bool
}
```

`OK=false` 表示沒有可用譯文（含譯文為空字串）。細節在 `003` §5。

## 6. 版面

寬度單位為半格（`h`，4 個原版像素）。半形字 1 h，全形字 2 h。**半形或全形由字型決定**，不由碼點範圍決定：字型建置時把每個字的寬度記入字型檔（`004` §3），載入後得 `wide(r)`。原文佔 `avail = 2 × len(t)` h。

1. `w(zh) ≤ avail`：照排；不足處尾端以 ASCII 空白補滿（遮住原文墨跡）。
2. `w(zh) > avail`：由左算起，保留不超過 `avail` h 的最長整字前綴；計入 `truncated`，記錄鍵。lint 在發行前擋下會截斷的譯文，這是最後一道防線。
3. 置中：`Result.Center` 為真時，譯文去掉頭尾空白後在 `avail` 內置中，左側補白 `floor((avail - w)/2)` h。其他情形靠左，保留譯文自己的開頭空白。
4. 譯文含 `\n` 或控制字元：視為格式錯誤，`Resolve` 回 `OK=false`。

## 7. 疊字

把排好的字串（含補白）切成連續的同寬度字元段（全形段 `CellW = 8`，半形段 `CellW = 4`），每段一筆 `xlate.Stamp`：

| 欄位 | 值 |
|---|---|
| `X` | `x0` 加上前面各段的寬度（原版像素） |
| `Y`、`CellH` | `y0`、`8` |
| `Cells`、`CellW`、`Text` | 該段的字元數、`8` 或 `4`、該段字元 |
| `Font`、`GlyphX`、`GlyphY`、`GlyphScale` | 語言通道字型（`Font.Name` 必須非空，且等於 `Layer.FontRegistry` 的鍵，否則視為組態錯誤並停用該語言），`0`、`0`、`1` |
| `Key` | 事件編號 `ID`（`g<N>`）。catalog 鍵與診斷資訊由 `EventRecord` 取得 |
| `State` | A 時設 `Printing`，B 時改為 `Pending` |
| `SwapColors`、`Transparent` | 不用 |

`Layer` 的 `W = 320`、`H = 200`，輸出倍率固定 2（全形字 16×16 恰好佔一個原版格）。

流程：

- T 類且 `Resolve` 回 `OK`：A 時對事件的每一筆疊字呼叫 `Layer.Add`；B 時把這一批設為 `Pending`。
- T 類且 `OK=false`：A 時對事件矩形呼叫 `Layer.Clear`，計入 `untranslated`（鍵集合記錄 `Result.Key`）。原文照常顯示。
- `Missed` 非空時，不論 `OK`，計入 `untranslated_args`（鍵集合記錄各缺譯引數）。
- `Layer.Frame` 可以在 A 與 B 之間執行：`Printing` 疊字不被定色也不被顯示；被 `Clear` 或 `Add` 波及的舊疊字只剩事件矩形之外的格。`Frame` 與 hook 在同一個 goroutine，只在 `RunUntil` 返回之間呼叫。

## 8. 定色與顯示

顏色由 `Layer.Frame` 在 `Pending` 疊字上取樣：矩形內出現最多的色號為背景，第二多為前景（`xlate.Colors`），再取該色號在畫面 RGB 中的值（RGB 依 `002` §6 的調色盤）。

同一事件的多段疊字（全形段、半形段、補白段）逐段定色，落在原文空白區的半形或補白段會取到單色（前景等於背景），字看不見。處置：每次 `Frame` 之後，對 `Key` 相同的一組疊字，把「前景與背景不同」的第一段的 `FG`、`BG` 複製給該組其他段（`unifyColors`），不改 `State`、指紋與其他欄位。找不到這樣的段（整組都是單色，例如原文本身是空白）時維持現狀並計入 `mono_segments`。

顯示：`Layer.Draw(dst, 2, missing)`，`dst` 是原版畫面放大 2 倍的 RGBA。`Pending` 疊字在下一次 `Frame` 之前不顯示；無頭收據擷取畫面前必須先呼叫一次 `Frame`（`005`）。

## 9. 診斷

計數器（只讀，可在收據輸出）：`events`、`composed`、`composed_miss`、`translated`、`untranslated`（含鍵集合）、`untranslated_args`（含鍵集合）、`blank`、`nonprintable`、`truncated`、`truncated_input`、`badformat`、`badlen`、`clipped`、`mono_segments`、`missing_glyph`（`Draw` 的 `missing` 回呼）、`unpaired`、`rebuild_lost`（`004`）。計數與記錄不得影響機器。

## 10. 驗收

1. 單元測試（純 Go，不需原版，期望值字面值）：事件分類（含 K、N、裁切）、半形全形切段（寬度表來自測試字型）、補白與截斷、置中、疊字欄位（`Font.Name` 缺漏回錯）、`unifyColors`、冪等去重（同 `SP` 重入忽略、`SP` 不同記 `unpaired`）。
2. 同狀態比對（需原版，缺檔 SKIP 並說明不算驗收）：以「完全不掛任何 hook 的 `RunUntil`」為基準，與「掛全部 hook、疊字開啟」「掛全部 hook、疊字關閉」三組在同一固定步數的 `B800:0000` 起 `4000h` bytes 雜湊、映像與 DGROUP 記憶體雜湊必須全部相同。
3. 位置 oracle：以 `CaptureVideoWrites`（掛 `sub_5E65` 的實際視訊寫入）取得每個 `25A5` 呼叫的實際寫入足跡；每筆疊字矩形必須落在其事件的寫入足跡內，足跡之外不得有疊字。
4. 覆蓋收據：每個接通路徑列出鍵、事件座標、疊字矩形與截圖；路徑至少含標題選單、城鎮上方選單列、公會選單。訊息視窗以收據記錄達成條件，未達成標「未量到」（`005`）。
5. 負對照：關閉「未譯事件 `Clear`」後，先印中文、再以未譯英文覆寫同一位置的測試應失敗。判定在覆寫事件與 B 之後、不呼叫 `Frame` 時直接檢查 `Layer.Stamps`：事件矩形內不得有未透明格（不得以「整筆疊字消失」判定；`Layer.Add`／`Clear` 對部分重疊只把被蓋格轉透明）。
