# 003 譯文 catalog 與字串解析

狀態：DRAFT 第二版（2026-10-03，依第一輪兩份審查修訂）。依賴 `001`。證據來源：`docs/re/005`、`007`、`008`，`textlog -args -sprintf` 動態記錄。

## 1. 範圍

譯文檔的格式、鍵的定義、執行期 `Resolve`（`EventRecord` 到譯文）、格式引擎（原版英文語意與目標語言語意）、組句、MESS 與 SCROLLS 的處理、手冊對照提示的保護、lint 與覆蓋檢查。字型與語言通道在 `004`，事件擷取與版面在 `001`。

## 2. 依據

| 事實 | 證據 | 等級 |
|---|---|---|
| 繪字事件的文字有四種來源形態：(a) 格式字串是字面文字、沒有轉換（例：說明列）；(b) 格式字串是 `%s`，引數是 DGROUP 靜態表內的字串指標（選單項目、種族、職業、狀態）；(c) 格式字串含字面文字與轉換，或含多個轉換（例：`%-10.9s%-9.8s%-9.8s%-5s`、`LEVEL%3u %s %s %s`）；(d) 組句：先以 `sprintf` 組進緩衝區（`DS:638E`），再以緩衝區當格式字串，或當 `%s` 引數 | 動態 `textlog -args -sprintf`；`008` §1 | 已證實 |
| 同一列清單的各欄是字串表項目，名字欄是玩家輸入的資料，位於 BSS 資料區而非靜態表 | 動態；`008` §1 | 已證實 |
| 卷軸行以格式 `%s`、引數為堆疊緩衝區近指標逐行畫出，列 2 至 21、欄 0 | `008` §2 | 已證實（靜態） |
| 格式規格只有 `%s %d %u %c %ld %lu`，旗標 `-`，寬度、精度；`%%` 引擎支援，靜態未見 | 靜態掃描 150 個實例 | 已證實 |
| 原版 `sub_5032` 的精度對字串與數字都是「最多輸出字元數」，不補零；旗標 `0` 只決定左補白字元；寬度不足補空白，`-` 補右側 | `008` §7 | 已證實（讀碼） |
| MESS 行與選項的繪出形式：最後一行只繪 `L mod 40` 字元，選項每欄 11 或 3 字元；每個 MESS 檔第 111 個 chunk 是尾記錄，不是訊息 | `008` §2、`007` | 讀碼推論（動態未量到）；尾記錄為已證實 |
| MESS 與 SCROLLS 解碼後的文字不含 `%`；SCROLLS 400 行全是 20 行 × 40 bytes，每行最長 39 字元 | `workplace/mess/` 全檔檢查 | 已證實 |
| 字面文字總量：靜態列舉 `res` 575、`ov1` 164、`ov2` 147 個字串（含檔名、格式字串與二進位誤判）；ui 候選鍵 652（剔除後 632）；prose 約 404 個單位、926 行 | `tools/enumerate_text.py`、`tools/ui_candidates.py`、`tools/prose_export.py` | 已證實（靜態計數） |
| 遊戲含手冊對照的提示字串（OV2 入口函式內，隨機條件觸發）。專案規則要求維持原文、不翻譯、不作答 | `008` §8 | 已證實（存在與位置）；不分析其資料 |

## 3. 譯文檔

路徑：`text/<family>.<lang>.tsv`，UTF-8、LF 換行，第一列是欄名，之後每列三欄以 TAB 分隔：

| 欄 | 內容 |
|---|---|
| `key` | 比對鍵，見 §4 |
| `translation` | 譯文；空字串表示尚未翻譯（草稿允許，發行 lint 不允許）。`<blank>` 表示刻意留白（覆繪成空白）。開頭 `\c` 表示置中（§8） |
| `source` | 來源定位（`res:DS偏移`、`ov1:DS偏移`、`ov2:DS偏移`、`mess<N>:<索引>#<行>`、`scroll<N>#<行>`、`dyn`）；可有多個，以 `;` 分隔 |

跳脫：`\t` 為 TAB，`\\` 為反斜線，`\xNN` 為任意位元組，其他反斜線序列是錯誤（開頭的 `\c` 是唯一例外）。不使用引號。**鍵與譯文的尾端空白一律不保留**（讀取與寫入都 rstrip）；開頭的空白保留；需要尾端空白的情形不存在。

家族：

| 家族 | 內容 | 鍵 |
|---|---|---|
| `ui` | 選單、標籤、狀態、名稱表、格式字串模板、一行完整的字面訊息 | 英文原文（§4） |
| `prose` | MESS 訊息行與選項、SCROLLS 卷軸行 | `h:` 加 12 位十六進位的摘要（§4） |

`prose` 不用英文鍵：這些是整本劇情文字，不放原版全文（`AGENTS.md` §7）；譯者需要的英文由 `tools/gamedata.py` 與 `tools/prose_export.py` 在本機從原版檔產生到 `workplace/`。`ui` 家族用英文原文當鍵（`AGENTS.md` §1、§6）。

## 4. 鍵

事件文字 `t` 的規範化：取 `Text[:40]`，去掉尾端的空白，開頭的空白保留。

| 鍵形 | 定義 |
|---|---|
| 字面鍵 | 事件的格式字串沒有轉換（`%%` 讀作 `%`）：鍵是規範化後的 `Text` |
| 模板鍵 | 格式字串含至少一個轉換：鍵是 rstrip 後的格式字串原文 |
| 引數鍵 | `%s` 引數的字串內容，規範化 |
| 摘要鍵 | `h:` 加 `hex(sha256(UTF-8 的規範化文字))[:12]`，用於 `prose` |

同一個英文字串在 `ui` 內只有一筆（全域唯一譯文）。MESS 行的摘要鍵取「實際繪出的規範化文字」：最後一行是 chunk 的前 `L mod 40` 字元（`L mod 40 = 0` 時 40 字元），選項是 11 或 3 字元的欄位文字。同一正規化文字同時存在於 `ui` 與 `prose` 時，`ui` 優先（§5）。

## 5. 解析

`Resolve(rec *EventRecord, lang) Result`（`001` §5）是純函式，只讀 `rec` 與 catalog。

```text
Resolve(rec):
  若 rec.Text 的文字屬於保護清單（§9）→ OK=false，記 protected（不計缺譯）
  fmt := parse(rec.Format)                     # 失敗（未支援規格、尾端 %）→ OK=false，記 badformat
  若 rec.Composed 非空：fmt、args := rec.Composed.Fmt、rec.Composed.Args（遞迴同結構）
  若 fmt 沒有轉換：
      t := 規範化(rec.Text)
      zh := ui[t]；沒有則 prose[摘要(t)]；譯文為空字串視同缺譯
      缺譯 → OK=false，Key=t
      → Result{Zh: zh, Center: zh 帶 \c 旗標}
  否則：
      tpl := ui[規範化(fmt)]；譯文為空字串視同缺譯
      若 tpl 缺：
          若 fmt 沒有英文字面（只有轉換、空白、標點與數字）→ tpl = fmt（恆等模板）
          否則 → OK=false，Key=規範化(fmt)
      對每個 %s 引數 a（含 ArgStrs 資訊）：
          若 a 本身是組句緩衝區（a.Composed 非空）→ 遞迴 Resolve，得到 a.zh
          否則若指標在靜態字串區間：zh_a := ui[a] 或 prose[摘要(a)]
          否則（資料型引數，如角色名、卷軸行緩衝區）：只查 prose[摘要(a)]，不查 ui
          查不到：保留原字串，並把 a 加入 Missed（資料型且不在 prose 內的不列入 Missed）
      zh := formatTarget(tpl, args)            # §7.2
      若 tpl 是恆等模板且沒有任何引數被替換成譯文 → OK=false（保留原畫面；Key = 該引數字串）
      → Result{Zh: zh}
```

**靜態字串區間**：常駐 DGROUP 的初始資料區（DS `0000` 至靜態列舉的最大字串偏移）與目前載入的 overlay 資料區（`DS:B8F0` 起，長度取自 overlay 標頭）。區間由 `tools/enumerate_text.py` 的輸出決定，執行期以組態載入。角色名、隊伍名等位於區間之外，故不查 `ui`，玩家輸入不會被當作譯文鍵（`AGENTS.md` §1）。

**引數讀取**：`rec.Args` 的 12 個字組依序消耗：`%s %d %u %c` 各 1 個字組，`%ld %lu` 各 2 個字組（低字組在前）。字組不夠時 `OK=false`。`%s` 字串含小於 `20h` 或大於 `7Eh` 的 byte 時 `OK=false`。

## 6. 疊字層的輸入

`Resolve` 只回傳譯文與旗標；版面（寬度、補白、截斷、置中）在 `001` §6，疊字在 `001` §7。事件原文的寬度是 `len(Text[:40])` 個格；事件格式化後的原文含尾端空白時，這些格都屬於可用寬度。

## 7. 格式引擎

### 7.1 原版英文語意（用於組句驗證）

`FormatEnglish(fmt, args)` 重現原版 `sub_5032`，輸出位元組串：

| 規格 | 行為 |
|---|---|
| `%s` | 字串；精度 `.P` 最多輸出 P 個字元；寬度 `W`（不足補空白，`-` 補右側，否則補左側） |
| `%d` | 16 位元有號十進位；精度 `.P` 最多輸出 P 個字元（含負號），不補零；寬度同上 |
| `%u` | 16 位元無號十進位；其餘同 `%d` |
| `%ld`、`%lu` | 32 位元（兩個字組，低在前）有號、無號十進位 |
| `%c` | 引數低位元組 |
| `%%` | `%` |
| 其他（旗標 `+ # 0`、`*`、`h`、`%x %o %e %f %g`） | 未支援，解析失敗 |

單元測試期望值用原版輸出：`%-4.3d` 對 5 為 `5   `、對 1234 為 `123 `、對 -12 為 `-12 `。

### 7.2 目標語言語意

`formatTarget(tpl, args)` 逐項輸出，寬度以半格（`h`）計：ASCII 字元 1 h，全形字元 2 h（`wide` 由字型寬度表決定，`001` §6）。一格 = 2 h。轉換規格同 §7.1，差別在寬度單位：欄位寬度 `W`、精度 `P` 以「原版的格」為單位（`2W`、`2P` h）。

- `%s`：精度 `.P`：保留不超過 `2P` h 的最長整字前綴；寬度不足 `2W` h 補 ASCII 空白（1 h）。
- 數字、`%c`：同原版語意，輸出是 ASCII（每字元 1 h），寬度補白以 h 計。
- 模板的轉換序必須與原格式字串相同（不支援 `%n$` 位置語法；需要重排語序時由譯者改寫句子，或回報給規格補充）。

`%s` 引數與數字都是 ASCII，所以在中文模板裡以半形顯示（4 原版像素寬）；欄位寬度與精度以「原版的格」為單位，使欄位對齊原文的格寬。

## 8. 置中

原版常把訊息行以空白置中（MESS 的場景標題）。置中由 catalog 明確標示（譯文開頭 `\c`），不由空白數推斷。`tools/prose_build.py` 在建置時依英文原文初判：開頭空白數 `L` 與尾端空白數 `T` 都至少 1，且（`|L - T| ≤ 2` 或文字含 `--`）者標 `\c`；其餘不標。置中時譯文去掉頭尾空白後在 `avail` 內置中（`001` §6）。

## 9. 保護清單（手冊對照提示）

`text/protected.tsv`（欄：`key`、`note`）列出原版以「查閱手冊或對照外部資料」為目的的提示字串（靜態找出，只含提示文字本身，不含任何資料表或答案）。事件文字（規範化後）或格式字串命中該清單時：不翻譯、不覆繪（`OK=false`，原畫面保留）、計入 `protected`，不計入缺譯。lint 擋下「保護清單的鍵出現在 catalog 內」。這些路徑到達時的處理依 `AGENTS.md` §1：標未知並回報使用者，不繞過、不作答。

## 10. lint

`tools/lint_catalog.py`（Docker 內執行）檢查 `text/*.tsv`，違規為錯誤：

| 檢查 | 說明 |
|---|---|
| 結構 | 三欄、鍵不空、跳脫合法、UTF-8、沒有 BOM、LF、鍵與譯文無尾端空白 |
| 鍵唯一 | 每個家族內唯一；同一規範化文字同時有非空譯文於 `ui` 與 `prose` 時列為衝突 |
| 摘要唯一 | `prose` 的 12 位摘要沒有碰撞 |
| 轉換一致 | 模板鍵與譯文的轉換序一致（類型含 `l`、順序、數目）；含不支援規格者為錯誤 |
| 字元 | 譯文沒有 TAB、換行、控制字元；每個非 ASCII 字元在字型來源（Unifont hex）有字形，並與字型寬度表一致（`004` §3）；對來源字型檢查，不對建置出來的子集檢查（避免循環） |
| 寬度 | 譯文的半格寬度不超過原文格式化寬度的兩倍（原文：字面字元數加各轉換的欄位寬度，無寬度時 `%s` 取 8、數字取最大位數；譯文：以同一組樣本引數格式化）。超過者為錯誤 |
| 術語 | `text/glossary.tsv`（欄：英文詞、譯詞、備註）。僅涵蓋 `ui`：原文鍵含該英文詞（大小寫不計，詞界）時，譯文必須含該譯詞。`prose` 的術語檢查在 `tools/prose_build.py` 以 `workplace/` 內的英文來源進行 |
| 保護 | 保護清單的鍵不得出現在 catalog |
| 空譯文 | 草稿模式只報數量；發行模式（`--release`）是錯誤 |
| 孤兒與缺譯 | `--sources` 指定靜態列舉結果（`tools/enumerate_text.py` 的輸出）：catalog 中沒有出現在列舉內的鍵是孤兒；列舉內沒有 catalog 的鍵是缺譯。兩者列出 |

覆蓋檢查：執行期的 `untranslated`、`untranslated_args` 鍵集合（`001` §9）與 catalog 比對，每條路線的收據列出缺譯鍵。

## 11. 靜態列舉

`tools/enumerate_text.py`、`tools/gamedata.py`、`tools/prose_export.py`（Docker 內執行，只讀原版檔，輸出到 `workplace/`）：

- 從映像取 DGROUP 字串，附 DS 偏移與程式碼、資料指標參照；
- `gamedata.py` 取 MESS 與 SCROLLS：每個訊息輸出各行**實際繪出的前綴**（`min(40, L - 40k)` 字元）、選項欄位（11 或 3 字元，rstrip）、尾記錄（索引 111）獨立標為 `trailer` 並排除出列舉；
- `prose_export.py` 輸出翻譯批次，排除尾記錄、控制字元記錄與 `L < 40` 的短訊息（內嵌選項的事件形式待量測）；
- 候選鍵是上界：非顯示用字串（檔名、記憶體區標籤）與二進位誤判需剔除（`tools/ui_prune.py`）。

## 12. 未決

1. 同一英文字串在不同畫面需要不同譯文（例：`Exit` 離開建築與關閉選單）。量到實例後再定上下文鍵的形式；在此之前全域唯一。
2. MESS 選項欄位與 `L < 40` 短訊息的實際事件形式：待動態量測（`007` §5.2）。
3. 由多段事件拼成的句子（前半、數字、後半分次輸出）：若出現，另開規格；在此之前這些事件各自被當成獨立字串，只有 catalog 有對應鍵者才覆繪。
4. 玩家輸入的名字在中文模板內以半形 ASCII 顯示；是否改以全形或音譯待決（`AGENTS.md` §12 待決第 2 項）。
5. 保護清單的觸發路徑（到達時的畫面行為）：動態未量到；收據標「未量到」。
