## 1. 範圍

## 2. 依據

| 事實 | 證據 | 等級 |
|---|---|---|
| 繪字事件的文字有四種來源形態：(a) 格式字串是字面文字、沒有轉換（例：說明列）；(b) 格式字串是 `%s`，引數是 DGROUP 靜態表內的字串指標（選單項目、種族、職業、狀態）；(c) 格式字串含字面文字與轉換，或含多個轉換（例：`%-10.9s%-9.8s%-9.8s%-5s`、`LEVEL%3u %s %s %s`）；(d) 組句：先以 `sprintf` 組進緩衝區（`DS:638E`），可再以 `strcat` 追加，最後以緩衝區當格式字串，或當 `%s` 引數 | 動態 `textlog -args -sprintf`；`008` §1；`001` §2 | 已證實 |
| `%s` 引數的指標落點（四份動態記錄的非靜態引數統計）：玩家記錄陣列（`5BB0` 起，間距 `011Ah`）、名冊陣列（`8E0C`、`8F26`、`A648`、`A762`、`A87C`，間距 `011Ah`）、怪物記錄陣列（`7522`、`755B`、`7594`，間距 `0039h`，索引運算 `i × 39h + 7522h`）、城鎮名緩衝區（`8071`，內容補空白到 10 格，由 `LEAVING %s` 與底部狀態列使用）、行緩衝區（`638E`）、堆疊（`FFxx`）、位置描述緩衝區（`C99D`、`C9C5`、`CA3D`，見 §12） | 第二輪審查 B-01、A-13；本輪統計 | 已證實（動態指標值）；怪物陣列筆數未定（§5） |
| 同一列清單的各欄是字串表項目，名字欄是玩家輸入或名冊的資料，位於 BSS 資料區而非靜態表 | 動態；`008` §1 | 已證實 |
| 卷軸行以格式 `%s`、引數為堆疊緩衝區近指標逐行畫出，列 2 至 21、欄 0 | `008` §2 | 已證實（靜態） |
| 格式規格只有 `%s %d %u %c %ld %lu`，旗標 `-`，寬度、精度；`%%` 引擎支援，靜態未見 | 靜態掃描 150 個實例 | 已證實 |
| 原版 `sub_5032` 的精度對字串與數字都是「最多輸出字元數」，不補零；旗標 `0` 只決定左補白字元；寬度不足補空白，`-` 補右側 | `008` §7 | 已證實（讀碼） |
| MESS 行與選項的繪出形式：最後一行只繪 `L mod 40` 字元，選項每欄 11 或 3 字元；每個 MESS 檔第 111 個 chunk 是尾記錄，不是訊息 | `008` §2、`007` | 讀碼推論（動態未量到）；尾記錄為已證實 |

## 3. 譯文檔

路徑：`text/<family>.<lang>.tsv`，UTF-8、LF 換行，第一列是欄名，之後每列三欄以 TAB 分隔：

| 欄 | 內容 |
|---|---|
| `key` | 比對鍵，見 §4 |
| `translation` | 譯文；空字串表示尚未翻譯（草稿允許，發行 lint 不允許）。`<blank>` 表示刻意留白（覆繪成空白），只允許整句，出現在模板內是格式錯誤。開頭 `\c` 表示整句置中（§8） |
| `source` | 來源定位（`res:DS偏移`、`ov1:DS偏移`、`ov2:DS偏移`、`TWNS.DAT:檔案偏移`（資料檔內的明文字串）、`mess<N>:<索引>#<行>`、`scroll<N>#<行>`、`dyn`）；可有多個，以 `;` 分隔 |

跳脫只有三種：`\t` 為 TAB，`\\` 為反斜線，開頭的 `\c` 為置中標記；其他反斜線序列是錯誤。（鍵是 20h 至 7Eh 的可印字元或雜湊，譯文不得含控制字元，所以不需要 `\xNN`。）不使用引號：任何讀取端（含工具的 `csv` 模組）必須關閉引號語意。**鍵與譯文的尾端空白不得出現在檔案內**：lint 讀原始行，鍵或譯文有尾端空白是錯誤（不得靜默去除）；執行期載入器對兩者 rstrip 作為容錯。開頭的空白保留；需要尾端空白的情形不存在。記憶體內以私用區字元 `U+E000` 表示置中標記，使檔案內字面的 `\\c` 開頭譯文不會與標記混淆。

家族：

| 家族 | 內容 | 鍵 |
|---|---|---|
| `ui` | 選單、標籤、狀態、名稱表、格式字串模板、一行完整的字面訊息、怪物名與城鎮名 | 英文原文（§4） |
| `prose` | MESS 訊息行與選項、SCROLLS 卷軸行 | `h:` 加 12 位十六進位的摘要（§4） |

`prose` 不用英文鍵：這些是整本劇情文字，不放原版全文（`AGENTS.md` §7）；譯者需要的英文由 `tools/gamedata.py` 與 `tools/prose_export.py` 在本機從原版檔產生到 `workplace/`。`ui` 家族用英文原文當鍵（`AGENTS.md` §1、§6）。

## 4. 鍵

事件文字 `t` 的規範化：取 `Text[:40]`，去掉尾端的空白，開頭的空白保留。

| 鍵形 | 定義 |
|---|---|
| 字面鍵 | 事件的格式字串沒有轉換（`%%` 讀作 `%`）：鍵是規範化後的 `Text` |
| 模板鍵 | 格式字串含至少一個轉換：鍵是 rstrip 後的格式字串原文 |
| 引數鍵 | `%s` 引數的字串內容，規範化 |
| 摘要鍵 | `h:` 加 `hex(sha256(UTF-8 的規範化文字))[:12]`，用於 `prose` |

同一個英文字串在 `ui` 內只有一筆（全域唯一譯文）。MESS 行的摘要鍵取「實際繪出的規範化文字」：最後一行是 chunk 的前 `L mod 40` 字元（`L mod 40 = 0` 時 40 字元），選項是 11 或 3 字元的欄位文字，**開頭空白保留、只去尾端**（選項欄位 154 個中 105 個以空白開頭）。查哪個家族只由指標種類決定（§5.1、§5.2：`static` 查 `ui`，`buffer` 查 `prose`），沒有跨家族的優先順序；同一規範化文字同時存在於 `ui` 與 `prose` 時，lint 要求兩者譯文相同（不同為錯誤，相同為警告，§10）。

## 5. 解析

`Resolve(rec *EventRecord, lang) Result`（`001` §5）是純函式，只讀 `rec` 與 catalog。

### 5.1 指標種類 `Kind`

EventRecord 擷取時依指標值分類（`001` §3.3），分類表是組態（`apps/phantasie/regions.tsv`，欄：`kind`、`start`、`stride`、`count`、`證據`），不寫死在程式。**預設拒絕**：不在表內的指標一律 `other`，不查任何 catalog。

| 種類 | 範圍 | 查表 |
|---|---|---|
| `static` | 常駐 DGROUP 靜態字串區 `[0000, 3244)`（`3244` 是 `FONT` 緩衝區起點；實測最大字串偏移 `321B`）；目前載入的 overlay 資料區：`ov1` `[B8F0, B8F0 + 0B6E)`、`ov2` `[B8F0, B8F0 + 0B10)`（長度取自 OVR 標頭 `data_len` 2926、2832，寫死在組態表，不在執行期讀檔） | `ui` |
| `buffer` | 堆疊（指標 ≥ 事件 A 時的 `SP`）與行緩衝區 `DS:638E` 起 80 bytes（MESS 行、卷軸行、選項欄位、`sprintf` 目的） | `prose` |
| `monster` | `7522 + 0039h × i`，`i = 0, 1, 2`（共 3 筆：之後緊接 `75CD`，是 `TWNS.INT` 的載入緩衝區起點，`(75CD - 7522) / 39h = 3`，`docs/re/009` §5） | `ui`（僅 `%s` 引數） |
| `town` | `8071 + 0123h × i`，`i = 0` 至 `11`，各 10 bytes（補空白的城鎮名，共 12 個：`TWNS.INT` 載入到 `DS:75CD` 後偏移 `0AA4h` 起，間距 `0123h`，`docs/re/009` §5；動態只見過 `i = 0`） | `ui`（僅 `%s` 引數） |
| `other` | 其餘：玩家與名冊記錄、位置描述緩衝區、未知 | 不查表 |

玩家輸入的名字、名冊角色名（位於玩家與名冊記錄陣列）屬 `other`，永遠不翻譯，也不因內容巧合等於 `ui` 鍵或 `prose` 鍵而被翻譯（`AGENTS.md` §1）。`other` 種類的引數計入 `arg_unclassified`，記 `(呼叫端, 引數序, 指標高位元組)` 集合（不記內容，避免玩家名進收據）；收據出現新組合時要人工分類並更新組態表。

格式字串指標 `FmtPtr` 同樣分類（`EventRecord.FmtKind`）：字面事件（沒有轉換）只在 `FmtKind` 為 `static` 時查 `ui`、為 `buffer` 時查 `prose`、為其他種類時不查（例：以名字緩衝區當格式字串直接畫出）。含轉換的模板事件同樣：只有 `FmtKind` 為 `static` 才以模板鍵查 `ui`；其他種類只允許恆等模板（沒有英文字面），否則缺譯且不填 `Key`（名字含 `%` 時會被解析成模板，不得去查 `ui`）。

### 5.2 偽碼

```text
Resolve(rec):
  1. 保護清單（§9）：規範化後的 rec.Text、rec.Format、以及 rec.Composed 與所有 ArgStrs[i].Piece（遞迴）的 Fmt 任一在清單內
       → OK=false, Why=protected
  2. p := rec.Composed 非空 ? rec.Composed : Piece{Fmt: rec.Format, FmtKind: rec.FmtKind, Literal: rec.Text,
                                                   Args: rec.Args, ArgStrs: rec.ArgStrs}
     （先決定用哪個格式字串，再解析；組句緩衝區的內容不當格式字串解析。Piece.Literal：沒有轉換的 Piece 的字面文字，
       頂層取 rec.Text（P 類修補後已是新字元），組句 Piece 取其組合字串）
  3. r := resolvePiece(p)
  4. 回傳 Result{Zh: r.zh, Center: r.center, Key: r.key, Hits: r.hits, Missed: r.missed, OK: r.ok, Why: r.why}

resolvePiece(p) -> {zh, center, replaced, ok, why, key, hits, missed}:
  f := parse(p.Fmt)                       # 失敗（未支援規格、尾端 %）→ ok=false, why=badformat
  若 f 沒有轉換（字面）:
      t := 規範化(p.Literal)               # 字面鍵一律取字面文字（不取 Format：P 類修補只改 Text 與 Cells）
      若 t 不含 A-Z a-z → ok=false, why=passthrough
      raw := p.FmtKind=static ? ui[t] : p.FmtKind=buffer ? prose[摘要(t)] : 無
      raw 缺 → ok=false, why=nokey；key=t 只在 FmtKind=static 時填，buffer、other 時 key 為空
                （緩衝區內容在組句驗證失敗時可能含玩家名，不得進鍵集合）
      raw 為空字串 → ok=false, why=blank_missing（key 同上規則）
      raw 為 <blank> → ok=true, zh=空, hits=[t 的鍵]
      否則 zh、center := 去掉 \c 前綴後的 raw、是否有前綴；hits=[t 的鍵]
      return
  # 含轉換（模板）
  k := rstrip(p.Fmt)
  若 p.FmtKind 不是 static:               # 以名字緩衝區等資料當格式字串時，名字含 % 會被解析成模板，不得查 ui
      若 p.Fmt 去掉轉換後含 A-Z a-z → ok=false, why=nokey（key 空）
      否則 tpl := p.Fmt；恆等模板
  否則:
      raw := ui[k]（空字串視同缺）
      若 raw 缺:
          若 p.Fmt 去掉轉換後不含 A-Z a-z → tpl := p.Fmt；恆等模板
          否則 → ok=false, why=nokey, key=k
      否則 tpl := 去掉 \c 前綴的 raw；center := 是否有前綴；hits += k
  對每個 %s 轉換 i，a := p.ArgStrs[i]:
      a.Content 含 <20h 或 >7Eh 的 byte → ok=false, why=badarg（整個事件不翻譯，計 badarg）
      若 a.Piece 非空:
          s := resolvePiece(a.Piece)       # 內層缺譯：該引數保留原字串，s.key 非空時加入 missed
          成功 → 使用 s.zh（內層的 center 忽略）；hits += s.hits
      否則 → 依 a.Kind 查表（lookupArg，下）
  Appends（組句後以 strcat 追加的字串）：每一筆是帶 Kind 的 ArgStr，同樣用 lookupArg；順序接在 formatTarget 結果之後
  zh := formatTarget(tpl, p.Args, 各 %s 的最終字串) ++ 各 Appends 的最終字串      # §7.2
  replaced := 任一 %s 引數或 Append 被換成譯文（含組句 Piece 解析成功者；否則戰鬥指令列的外層恆等模板會被判 identity）
  若 tpl 是恆等模板:
      若 p 沒有 %s 轉換 → ok=false, why=passthrough
      否則若 !replaced → ok=false, why=identity（保留原畫面）
  return ok

lookupArg(a):
  若 rstrip(a.Content) 為空 → 原樣保留（不計 Missed）
  依 a.Kind:
      static  → v := ui[規範化(a.Content)]
      monster、town → v := ui[規範化(a.Content)]
      buffer  → v := prose[摘要(規範化(a.Content))]
      other   → 原樣保留，不查表
  v 缺或為空字串 → 原樣保留；static、monster、town 把規範化(a.Content) 加入 missed，buffer、other 不加
  v 命中 → hits += 該鍵
  v 帶 \c 前綴：僅當 tpl 恆等且是單一 %s（卷軸行 `%s`）時，center := true 並去掉前綴；
              其他情形視為資料錯誤 → ok=false, why=badarg
```

規則補充：

- **`Result.Zh` 不含置中標記**；置中只由 `Center` 表達（`001` §6）。內層組句的置中不傳遞。
- **`<blank>`**：譯文恰為 `<blank>` 時回 `OK=true` 且 `Zh` 為空；版面層補滿 `avail` 寬的 ASCII 空白（`001` §6）。`<blank>` 只允許整句；出現在模板內，或當作 `%s` 引數的譯文，都是格式錯誤（lint 擋下）。
- **恆等模板**：模板鍵沒有英文字面（去掉轉換規格後不含 `A-Z a-z`），catalog 沒有對應鍵時以格式字串自身當模板。判準看「解析後的 `tpl` 與格式字串相等且沒有任何引數被替換成譯文」，不論 `tpl` 來自 catalog 或後備；catalog 內有這種鍵（譯文等於鍵）只是冗餘，lint 警告（目前 8 筆）。
- **`Why = passthrough`**：原文沒有字母（分隔線、`*`、數字、單一 `%c` 事件）。不是缺譯，不計 `untranslated`，鍵集合不記（避免玩家輸入的字母進收據）。
- **`Result.Key` 的來源限制**：只在來源是格式字串或靜態字串時填入（字面鍵、模板鍵、靜態引數鍵）；來源是 `buffer`、`other` 的內容不填，改記呼叫端與格式字串。`001` §9 的鍵集合不含玩家輸入。
- **組句的 `Piece.FmtKind`** 取 `sprintf` 呼叫時格式字串指標的種類（通常是 `static`）。

**引數讀取**：`p.Args` 的 12 個字組依序消耗：`%s %d %u %c` 各 1 個字組，`%ld %lu` 各 2 個字組（低字組在前）。字組不夠時 `OK=false`（`badarg`）。`%c` 的字組低位元組為 0 時，原版輸出含 NUL；比對與顯示都截到第一個 NUL（`%c` 為 0 視為空字元）。

## 6. 疊字層的輸入

`Resolve` 只回傳譯文與旗標；版面（寬度、補白、截斷、置中）在 `001` §6，疊字在 `001` §7。事件原文的寬度是 `len(Text[:40])` 個格；事件格式化後的原文含尾端空白時，這些格都屬於可用寬度。

## 7. 格式引擎

### 7.1 原版英文語意（用於組句驗證與測試）

`FormatEnglish(fmt, args)` 重現原版 `sub_5032`，輸出位元組串：

| 規格 | 行為 |
|---|---|
| `%s` | 字串；精度 `.P` 最多輸出 P 個字元；寬度 `W`（不足補空白，`-` 補右側，否則補左側） |
| `%d` | 16 位元有號十進位；精度 `.P` 最多輸出 P 個字元（含負號），不補零；寬度同上 |
| `%u` | 16 位元無號十進位；其餘同 `%d` |
| `%ld`、`%lu` | 32 位元（兩個字組，低在前）有號、無號十進位 |
| `%c` | 引數低位元組 |
| `%%` | `%` |
| 其他（旗標 `+ # 0`、`*`、`h`、`%x %o %e %f %g`、`%n$`） | 未支援，解析失敗 |

單元測試期望值用原版輸出：`%-4.3d` 對 5 為 `5   `、對 1234 為 `123 `、對 -12 為 `-12 `。

### 7.2 目標語言語意

`formatTarget(tpl, args, strs)` 逐項輸出，寬度以半格（`h`）計：ASCII 字元 1 h，全形字元 2 h（`wide` 由字型寬度表決定，`001` §6）。**一格 = 2 h。欄位寬度 `W` 一律以「原版的格」為單位，輸出 `2W` h 的欄位**（數字、`%c`、`%s` 都一樣）；轉換規格的類型、`l`、旗標 `-`、順序與精度必須與原格式字串相同，寬度 `W` 可為對齊右緣而調整（`STYLE.md`）。

| 轉換 | 行為 |
|---|---|
| `%s` | 寬度 `W`：不足 `2W` h 補 ASCII 空白（`-` 補右側，否則補左側）。精度 `.P`：引數是**譯文**時保留不超過 `2P` h 的最長整字前綴；引數是**原樣保留的 ASCII 字串**（資料型、缺譯）時最多 `P` 個字元，與原版相同 |
| `%d %u %ld %lu` | 輸出 ASCII 數字（每字元 1 h）；精度 `.P` 是最多輸出 `P` 個字元（原版語意，含負號，不補零，不是欄位 h 數）；寬度 `W` 不足 `2W` h 時補空白（`-` 補右側，否則補左側） |
| `%c` | 字元 1 h，**佔一格（2 h）**：無寬度時右側補 1 h 空白（原版一個字元佔一格，其後欄位的位置依賴它）；有寬度 `W` 時輸出 `2W` h，補白方向同上 |

單元測試字面期望值：`%c` 對 `A` 輸出 `A` 加 1 個半形空白（2 h）；`%4u` 對 5，目標語言輸出 7 個半形空白加 `5`（共 8 h）；`%-4.3d` 對 1234，輸出 `123` 加 5 個半形空白（8 h）；`%-10.9s` 對譯文「哥布林」（6 h）輸出 6 h 加 14 h 空白（共 20 h）；同格式對原樣保留的 ASCII 名字 `ABCDEFGHIJ`（10 字元）輸出 `ABCDEFGHI`（9 字元）加補白至 20 h。

`%s` 引數與數字都是 ASCII 時在中文模板裡以半形顯示（4 原版像素寬），欄位寬度以格為單位使欄位對齊原文的格寬。

### 7.3 兩套實作共用測試向量

格式引擎有三份實作：Go 的 `FormatEnglish` 與 `formatTarget`、Python 的 `catalog_lib`（lint 與工具）。三者共用 `tests/vectors/` 下的三個檔案：`parse.tsv`（欄：`fmt`、`expect`；格式字串 → 轉換序或 `ERR`）、`english.tsv`（欄：`fmt`、`args`、`expect`；原版英文語意）、`target.tsv`（欄：`tpl`、`args`、`expect`、`h`；目標語言語意與半格寬度）。向量檔內 `_` 代表半形空白，期望值以 `[ ]` 包住；Go 與 Python 各跑一次，期望值是字面值（不以另一個語言的輸出當期望）。Python 的 `CONV` 收斂到本節規格：不接受旗標 `0`、`+`、`#`、`*`、`h`，不接受 `x X o e f g`，不接受 `%n$`。

## 8. 置中

原版常把訊息行以空白置中（MESS 的場景標題、戰鬥與狀態訊息列）。置中由 catalog 明確標示（譯文開頭 `\c`），不由空白數推斷，也不在執行期以公式判斷（公式有巧合，例如選單項目恰好符合）。

- `prose`：`tools/prose_build.py` 在建置時依英文原文初判：開頭空白數 `L` 與尾端空白數 `T` 都至少 1，且（`|L - T| ≤ 2` 或文字含 `--`）者標 `\c`；SCROLLS 卷軸前兩行（標題）一律標 `\c`；其餘不標。
- `ui`：訊息列的置中候選由 `tools/ui_center.py` 以「呼叫端白名單」（`A1E2`、`5663`、`2EA0`、`2EEE`、`2F10`、`9C4C`、`99B1`、`991D`）從動態記錄產生（該呼叫端的同一鍵事件至少 2 次且 `Col = (40 - len) / 2` 全部成立；現有 13 筆），人工確認後寫入；`\c` 加在模板或字面鍵的譯文上，對任何長度的引數都以事件自身寬度置中。
- 置中時譯文去掉頭尾空白後在 `avail` 內置中（`001` §6）。非置中者保留譯文自己的開頭空白，工具不得 `strip` 兩端。

## 9. 保護清單（手冊對照提示）

`text/protected.tsv`（欄：`key`、`note`）列出原版以「查閱手冊或對照外部資料」為目的的提示字串（靜態找出，只含提示文字本身，不含任何資料表或答案）。**比對對象**：事件文字、事件格式字串、組句的格式字串三者規範化後任一命中清單的鍵（清單內多筆是含轉換的格式字串，只比 `Text` 永遠比不到）。命中時：不翻譯、不覆繪（`OK=false`，原畫面保留）、對事件矩形仍 `Layer.Clear`（不覆繪不等於不清除舊疊字）、計入 `protected`，不計入缺譯。`tools/ui_prune.py` 的剔除表讀 `protected.tsv`，不另維護一份。lint 擋下「保護清單的鍵出現在 catalog」。這些路徑到達時的處理依 `AGENTS.md` §1：標未知並回報使用者，不繞過、不作答。

## 10. lint

`tools/lint_catalog.py`（Docker 內執行）檢查 `text/*.tsv`，違規為錯誤，**每個語言檔獨立檢查**（鍵唯一性不跨語言）。壞跳脫等讀取錯誤以「該列」為單位報告並繼續檢查其餘列，不使整檔放棄而遮蔽其他錯誤：

| 檢查 | 說明 |
|---|---|
| 結構 | 三欄、鍵不空、跳脫合法（只有 `\t`、`\\`、開頭 `\c`）、UTF-8、沒有 BOM、LF、**讀原始行**，鍵與譯文無尾端空白（不得靜默 rstrip） |
| 鍵唯一 | 每個家族內唯一；規範化後（去尾端空白）重複者為錯誤；同一規範化文字同時有非空譯文於 `ui` 與 `prose` 時列為衝突 |
| 摘要唯一 | `prose` 的 12 位摘要沒有碰撞 |
| 轉換一致 | 模板鍵與譯文的轉換序一致（類型含 `l`、旗標、精度、順序、數目）；含不支援規格（`%x`、`%o`、`%n$`、`0 + # * h` 旗標、尾端 `%`）者為錯誤；寬度可不同 |
| 欄位右緣 | 同一鍵的每個轉換，以樣本引數格式化後，原文與譯文的右緣（h）差的絕對值超過 `2` h 警告（欄位寬度可為對齊而調整，`STYLE.md`） |
| 置中與留白 | `\c` 只能在開頭且出現一次；`<blank>` 只能是整句譯文，不得在模板內 |
| 字元 | 譯文沒有 TAB、換行、控制字元；每個非 ASCII 字元在字型來源（Unifont hex）有字形，**寬度由字型寬度表決定**（`004` §3，不用碼點範圍）；對來源字型檢查，不對建置出來的子集檢查（避免循環） |
| 寬度 | 譯文的半格寬度不超過原文格式化寬度的兩倍（原文：字面字元數加各轉換的欄位寬度，無寬度時 `%s` 取 8、數字取最大位數，數字精度取最多字元數；譯文：以同一組樣本引數格式化）。超過者為錯誤。`prose` 依單元列實際長度檢查（最後一行 `L mod 40`、選項欄位 11 或 3 字元，各自的 `avail = 2 × 長度` h） |
| 術語 | `text/glossary.tsv`（欄：英文詞、譯詞、備註）。僅涵蓋 `ui`：原文鍵含該英文詞（大小寫不計，詞界）時，譯文必須含該譯詞。縮寫（`HP`、`MP`、`XP`、`GP`）與全稱各自列入詞表。`prose` 的術語檢查在 `tools/prose_build.py` 以 `workplace/` 內的英文來源進行 |
| 保護 | 保護清單的鍵不得出現在 catalog |
| 空譯文 | 草稿模式只報數量；發行模式（`--release`）是錯誤。`--release` 同時要求指定字型表（`--font-tar`）、詞表與保護清單，缺任一為錯誤 |
| 原地改寫的兩極性 | 鍵以 `+` 或 `-` 開頭且其後是字母者（開關標籤），相反符號的鍵（`+` 對 `-`）也必須存在（`001` §4 的 P 類：標籤字串被程式原地改寫，兩種極性都會被畫出） |
| 冗餘 | 模板鍵沒有英文字面且譯文等於鍵：警告 |
| 孤兒與缺譯 | `--sources` 指定靜態列舉結果（`tools/enumerate_text.py` 的輸出）：catalog 中沒有出現在列舉內的鍵是孤兒；列舉內沒有 catalog 的鍵是缺譯。兩者列出 |
| 動態缺譯 | `--harvest` 指定動態蒐集結果（`workplace/harvest/texts.tsv`）：`in_static=Y` 的字串必須全在 catalog，缺者為錯誤；其他缺者列為警告 |

覆蓋檢查：執行期的 `untranslated`、`untranslated_args` 鍵集合（`001` §9）與 catalog 比對，每條路線的收據列出缺譯鍵。

## 11. 靜態列舉

`tools/enumerate_text.py`、`tools/gamedata.py`、`tools/prose_export.py`（Docker 內執行，只讀原版檔，輸出到 `workplace/`）：

- 從映像取 DGROUP 字串，附 DS 偏移與程式碼、資料指標參照；
- `gamedata.py` 取 MESS 與 SCROLLS：每個訊息輸出各行**實際繪出的前綴**（`min(40, L - 40k)` 字元）、選項欄位（11 或 3 字元，只 rstrip，開頭空白保留）、尾記錄（索引 111）獨立標為 `trailer` 並排除出列舉；
- `prose_export.py` 輸出翻譯批次，排除尾記錄、控制字元記錄與 `L < 40` 的短訊息（內嵌選項的事件形式待量測）；
- 候選鍵是上界：非顯示用字串（檔名、記憶體區標籤）與二進位誤判需剔除（`tools/ui_prune.py`）。剔除規則的修正（第二輪審查 A-11）：「是檔名」的判定只對作為 `fopen` 參數的字串成立（由程式碼參照判斷），不用「含 `.`」或檔名單字清單（`guild` 等詞同時是選單項目）；`plausible()` 對全大寫縮寫字不要求母音；`harvest` 的 `in_static=Y` 字串一律不得被剔除；
- **原地改寫的靜態字串**：對「對靜態字串位址存入常數」的指令（`mov byte ptr [bx], imm`，`bx` 來自指向靜態字串的字組表）做資料流掃描，把兩種極性的字串都列入候選（選項開關的 `+` 與 `-`，`001` §4 的 P 類）。catalog 要同時收開關兩種極性的鍵。

## 13. 驗收

1. **`FormatEnglish` 向量**（純 Go，字面值，同時存成 `tests/vectors/english.tsv` 給 Python 跑）：`%-4.3d` 對 5、1234、-12；`%s` 精度與寬度；`%ld`、`%lu` 字組順序（`%c` 為 0 輸出含 NUL，NUL 無法寫進 TSV 向量，改在 Go 單元測試驗證比對與顯示都截到第一個 NUL）；`%%`；未支援規格（`%x`、`%05d`、`%2$s`、`%*d`、尾端 `%`）回失敗。
2. **`formatTarget` 向量**：§7.2 的五個字面期望值；全形字寬度與精度截斷；`-` 補右側。
3. **`Resolve` 表驅動測試**（假 catalog、假 `EventRecord`）：字面鍵命中、模板命中、恆等模板無替換回 `identity`、恆等模板無 `%s` 回 `passthrough`、部分替換（一個引數缺譯、另一個替換）、`Missed` 只含 `static`、`monster`、`town`、空譯文回 `blank_missing`、`<blank>` 回空 `Zh` 且 `OK`、巢狀組句（內層成功、內層缺譯）、組句加 `Appends`、`FmtKind` 為 `other` 的字面事件不查表、**卷軸標題 `%s` 事件 `Center` 為真且 `Zh` 不含 `\` 與 `c`**、`badarg`（引數含控制字元、字組不足）、含 `%` 的緩衝區不關聯。
4. **負對照**：
   - 玩家名（`other` 種類）與某個 `ui` 鍵同字，顯示不得翻譯；把 `Kind` 檢查關掉（一律查 `ui`）應失敗。
   - 玩家名與某個選項欄位的 `prose` 鍵同字（`other` 種類），不得翻譯；把 `buffer` 與 `other` 混為一類應失敗。
   - 怪物名與城鎮名（`monster`、`town`）查 `ui`，缺譯時出現在 `Missed`；關掉 `monster`、`town` 種類應失敗。
   - 保護清單命中（含模板型的格式字串命中）：`OK=false`、`Why=protected`、事件矩形被 `Clear`；只比對 `Text` 的實作應失敗。
5. **共用向量**：Go 與 Python 的解析器（`parse.tsv`）與格式化（`english.tsv`、`target.tsv`）各跑一次，結果一致且等於字面期望值。
6. **lint 反例**（`tools/tests/lint_cases.py`，Docker 內執行）：鍵尾端空白、譯文尾端空白、規範化後鍵重複、保護清單的鍵進 catalog、`ui` 與 `prose` 同文衝突、`--sources` 孤兒與缺譯、`%x`、`%2$s`、`%05d`、壞跳脫（`\xZZ`）與另一列超寬（兩個錯誤都要報）、`…`（U+2026）三個對鍵 `OK`（寬度為真實字寬 6 h）、`<blank>` 在模板內、`\c` 不在開頭，每一個都必須被擋下。
7. **回歸統計**（有原版時）：以動態記錄重跑「`ui` 命中的靜態字串事件全部有譯文」與「資料型引數被保留原樣的事件數」，後者須能由 `arg_unclassified` 集合完全解釋。
