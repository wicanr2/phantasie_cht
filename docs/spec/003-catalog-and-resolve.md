# 003 譯文 catalog 與字串解析

狀態：DRAFT（2026-10-03）。依賴 `001`。證據來源：`docs/re/005`（格式字串統計）、`007`（MESS 與 SCROLLS）、`textlog -args` 動態記錄。

## 1. 範圍

譯文檔的格式、鍵的定義、執行期 `Resolve`（事件到中文字串）、格式引擎、MESS 與 SCROLLS 的處理、lint 與覆蓋檢查。字型與語言通道在 `004`。

## 2. 依據

| 事實 | 證據 | 等級 |
|---|---|---|
| 繪字事件的文字有三種來源形態：(a) 格式字串是字面文字、沒有轉換（例：`Use ESC key to exit most menus.`）；(b) 格式字串是 `%s`，引數是 DGROUP 內的字串指標（選單項目，例：`Spells`）；(c) 格式字串含字面文字與轉換，或含多個轉換（例：`%-10.9s%-9.8s%-9.8s%-5s`，引數 4 個近指標） | 動態記錄 | 已證實 |
| 同一列清單的各欄是字串表的項目（例：種族、職業、狀態），名字欄是玩家輸入的資料（動態記錄中的預設隊伍名） | 動態記錄 | 已證實 |
| 格式規格只有 `%s %d %u %c %ld %lu %%`，旗標 `-`，寬度、精度 | `001` §2 | 已證實（靜態掃描） |
| MESS 的文字行是 40 字元，格式字串指標是緩衝區位址（內容就是文字）；選項列的格式字串在堆疊。MESS 與 SCROLLS 解碼後的文字不含 `%`，所以字面行不會被當成轉換 | `007`；`workplace/mess/` 全檔檢查 | 強推論（靜態）；無 `%` 為已證實 |
| SCROLLS 每卷 20 行 × 40 bytes，行以 NUL 補齊 | `007` | 強推論（解碼後資料）；顯示路徑未讀 |
| 字面文字總量：常駐 DGROUP 476 字串、OV1 142、OV2 132（含檔名與格式字串）；MESS 10 檔約 2.0 萬字元；SCROLLS 20 卷 | `003`、`007` | 已證實（靜態計數） |

## 3. 譯文檔

路徑：`text/<family>.<lang>.tsv`，UTF-8、LF 換行，第一列是欄名，之後每列三欄以 TAB 分隔：

| 欄 | 內容 |
|---|---|
| `key` | 比對鍵，見 §4 |
| `translation` | 譯文；空字串表示尚未翻譯（草稿允許，發行 lint 不允許） |
| `source` | 來源定位（`res:DS偏移`、`ov1:DS偏移`、`ov2:DS偏移`、`mess<N>:<索引>`、`scroll<N>:<行>`）；可有多個，以 `;` 分隔 |

跳脫：`\t` 為 TAB，`\\` 為反斜線，`\xNN` 為任意位元組，其他反斜線序列是錯誤。不使用引號。譯文末端的空白不保留（寫入與讀取都 rstrip）；開頭的空白保留。

家族：

| 家族 | 內容 | 鍵 |
|---|---|---|
| `ui` | 選單、標籤、狀態、名稱表、格式字串模板、一行完整的字面訊息 | 英文原文（§4） |
| `prose` | MESS 訊息行、SCROLLS 卷軸行 | `h:` 加 12 位十六進位的摘要（§4） |

`prose` 不用英文鍵：這些是整本劇情文字，不放原版全文（`AGENTS.md` §7）；譯者需要的英文由 `tools/gamedata.py` 在本機從原版檔產生到 `workplace/mess/`。`ui` 家族用英文原文當鍵（`AGENTS.md` §1、§6）。

## 4. 鍵

事件文字 `t` 的規範化：取 `Text[:40]`，去掉尾端的空白，開頭的空白保留。

| 鍵形 | 定義 |
|---|---|
| 字面鍵 | 事件的格式字串沒有轉換（`%%` 不算轉換，讀作 `%`）：鍵是規範化後的 `Text` |
| 模板鍵 | 格式字串含至少一個轉換：鍵是格式字串原文（不 rstrip，因為尾端的字面文字與空白屬於模板） |
| 引數鍵 | `%s` 引數的字串內容，規範化（rstrip，保留開頭空白） |
| 摘要鍵 | `h:` 加 `hex(sha256(UTF-8 的 t 規範化))[:12]`，用於 `prose` |

同一個英文字串在 `ui` 內只有一筆（全域唯一譯文）。需要依畫面區分不同譯文的情形留待實測（§11）。

## 5. 解析

```text
Resolve(ev):
  fmt := parse(ev.Format)                    # 解析失敗（未支援規格、尾端 %）→ 回 ok=false
  if fmt 沒有轉換:
      t := 規範化(ev.Text)
      zh := ui[t] 或 prose[摘要(t)]            # 兩者都沒有 → ok=false，鍵 = t
      → layout(ev, zh)                       # 見 §6，置中規則 §8
  else:
      tpl := ui[ev.Format]
      if tpl 缺：
          若 fmt 沒有英文字面（只有轉換、空白、標點與數字）→ tpl = ev.Format（恆等模板）
          否則 → ok=false，鍵 = ev.Format
      args := 讀引數（依 fmt 的轉換序）
      對每個 %s 引數：字串 a（rstrip）→ ui[a] 存在則取之，否則保留原字串
      zh := format(tpl, args)                # §7
      → layout(ev, zh)
```

引數讀取：`ev.Args` 的 12 個字組依序消耗：`%s %d %u %c` 各 1 個字組，`%ld %lu` 各 2 個字組（低字組在前）。字組不夠（轉換需要的字組超過 12）時 `ok=false`。`%s` 的字組是 DGROUP 近指標，由唯讀記憶體讀以 NUL 結尾的字串，最多 80 bytes；字串含小於 `20h` 或大於 `7Eh` 的 byte 時 `ok=false`（避免把圖示字元顯示成問號）。

模板的轉換序必須與原格式字串相同（`%n$` 位置語法 `%2$s` 允許用於重排，lint 要求每個原轉換恰好出現一次）。

## 6. 疊字層的輸入

`Resolve` 回傳 `zh`（`[]rune`）、鍵與 `ok`。`001` §6 負責版面（寬度、補白、截斷），`001` §7 產生疊字。事件原文的寬度是 `len(Text[:40])` 個格；事件格式化後的原文含尾端空白時，這些格都屬於可用寬度（原版畫面上同樣被這些空白清除過）。

## 7. 格式引擎

對模板 `tpl` 與 `args` 逐項輸出，寬度以半格（`h`）計：ASCII 字元 1 h，全形字元 2 h（`001` §6）。一格 = 2 h。

| 規格 | 行為 |
|---|---|
| `%s`（引數已解析為字串 `a`） | 精度 `.P`（格）：保留不超過 `2P` h 的最長整字前綴。寬度 `W`（格）：不足 `2W` h 則補白（`-` 旗標補右側，否則補左側），補白字元是 ASCII 空白（1 h） |
| `%d` | 16 位元有號十進位。`.P` 為最少位數（前補 0）。寬度與補白同上 |
| `%u` | 16 位元無號十進位 |
| `%ld`、`%lu` | 32 位元（兩個字組，低在前）有號、無號十進位 |
| `%c` | 引數低位元組，在 `20h` 至 `7Eh` 輸出該字元，其餘 `ok=false` |
| `%%` | `%` |
| 其他（旗標 `+ # 0`、`*`、`h`、`%x %o %f`…） | 未支援，`ok=false`。旗標 `0` 對 `%d`、`%u` 以前補 0 實作（`%-4.3d` 之類已涵蓋；若動態量到再補） |

`%s` 引數與數字都是 ASCII，所以在中文模板裡以半形顯示（4 原版像素寬）；寬度與精度以「原版的格」為單位，使欄位對齊原文的格寬。

## 8. 置中

原版常把訊息行以空白置中（MESS 的場景標題）。規則：原文 `t` 的開頭空白數 `L` 與尾端空白數 `T` 都至少 1，且 `|L - T| ≤ 1`，視為置中。置中時譯文去掉頭尾空白後，在 `avail`（`2 × len(Text[:40])` h）內置中，左側補白 `floor((avail - w)/2)` h；譯文過寬的處理同 `001` §6。其他情形譯文靠左，保留譯文自己的開頭空白。

## 9. lint

`tools/lint_catalog.py`（Docker 內執行）檢查 `text/*.tsv`，違規為錯誤：

| 檢查 | 說明 |
|---|---|
| 結構 | 三欄、鍵不空、跳脫合法、UTF-8、沒有 BOM、LF |
| 鍵唯一 | 每個家族內唯一，`ui` 與 `prose` 之間不衝突（`h:` 前綴不會出現在 `ui` 英文鍵開頭） |
| 摘要唯一 | `prose` 的 12 位摘要沒有碰撞 |
| 轉換一致 | 模板鍵與譯文的轉換序一致：類型、數目、`%n$` 重排後每個原轉換恰好一次 |
| 字元 | 譯文沒有 TAB、換行、控制字元；每個非 ASCII 字元存在於語言通道字型的字元表（`004`）；全形字元以 `wide` 判定（`001` §6） |
| 寬度 | 以「樣本引數」格式化譯文，寬度（h）不超過原文格式化寬度（h × 1 per 格）。樣本引數是原文引數字串（`%s` 取該位置出現過的最長英文，數字取各規格能顯示的最大位數）。超過的列出「截斷風險」 |
| 術語 | `text/glossary.tsv`（欄：英文詞、譯詞、備註）。原文鍵含該英文詞（大小寫不計，詞界）時，譯文必須含該譯詞 |
| 空譯文 | 草稿模式只報數量；發行模式（`--release`）是錯誤 |
| 孤兒鍵 | `--sources` 指定靜態列舉結果（`tools/enumerate_text.py` 的輸出）：catalog 中沒有出現在列舉內的鍵是孤兒；列舉內沒有 catalog 的鍵是缺譯。兩者列出 |

覆蓋檢查：執行期的 `untranslated` 鍵集合（`001` §9）與 catalog 比對，每條路線的收據列出缺譯鍵。

## 10. 靜態列舉

`tools/enumerate_text.py`（Docker 內執行，只讀原版檔，輸出到 `workplace/`）：

- 從 IDA 匯出（`survey*.json` 的 `strings`）與 overlay 資料段取字串，附 DS 偏移與參照函式；
- 以 `tools/gamedata.py` 取 MESS 與 SCROLLS 的所有行；
- 輸出候選鍵清單：欄為 `family`、`key_form`（字面、模板、引數、摘要）、`source`、`english`（只寫 `workplace/`，不進版控）。
- 候選鍵是上界：非顯示用字串（檔名、記憶體區標籤）也會在內，需人工標示。

## 11. 未決

1. 同一英文字串在不同畫面需要不同譯文（例：`Exit` 離開建築與關閉選單）。量到實例後再定上下文鍵的形式；在此之前全域唯一。
2. MESS 的選項欄位（欄寬 11 或 3）與短訊息（`L < 40`）的事件形式：待動態量測（`007` §5.2）。
3. SCROLLS 的顯示路徑與事件形式（逐行 `%s`？）：待讀 `OV1` 的 `sub_AA96` 附近並動態量測。
4. 由多段事件拼成的句子（前半、數字、後半分次輸出）。若出現，另開規格（模板 §13）；在此之前這些事件各自被當成獨立字串，只有 catalog 有對應鍵者才覆繪。
5. 引數字串由玩家輸入（名字）時的顯示：`%s` 引數不在 `ui` 內則保留原字串，以半形 ASCII 顯示。是否改以全形或音譯待決（`AGENTS.md` §12 待決第 2 項）。
