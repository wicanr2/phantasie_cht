# 010 變暗項目的嚴格遮罩稽核

狀態：CONFORMED（2026-10-05）。兩輪唯讀審查、實作審查及正式驗收通過。依據：[RE024](../re/024-disabled-spell-list.md)。前置：001、004 CONFORMED，002 的既有 READY 契約；引擎基準 `60b76b3`，實作 `8d9807df4f191c02eef46a22b6f7bbecb426ef5b`。

## 問題與範圍

正常施法耗盡魔力後，原版 `0740` 抹掉不可選法術的掃描線 2、4。中文覆繪仍顯示既有譯文；嚴格原字模檢查將原版清除像素判成雜色，正式收據失敗。只修稽核模型，保留 002 §5 的既有顯示限制：不重現中文變暗外觀。原版選項、判定、輸入、記憶體及 VRAM 保持原樣。

## 契約

1. `OnInvert(row, col, width, true)` 完成時，將已知變暗範圍附在對應稽核日誌事件，按事件原版格記錄。只標示與操作同一個實際像素列、完整落在操作矩形內的原版格。捲動後以現有疊字組的實際 Y 判斷列；同組 Y 不一致、沒有對應疊字、超出事件或矩形為空時不標示。普通反白不新增變暗資格。
2. 記號綁定原始事件 id，不綁譯文鍵或字串。新繪字事件不得繼承舊資格。它隨既有有界稽核日誌淘汰；不增加無界快取，不寫存檔、catalog、原版記憶體或公開路線。
3. 嚴格檢查先接受原有完整字模的 100% 對應。只有該檢查失敗、且事件含已知變暗格時，才核對另一個精確模型：這些格的掃描線索引 2、4，所有受查像素必須是同一清除色 0，或後續反白所得的 3。每個原版格的兩條掃描線必須使用同一色，不接受其他色或混色。其餘格及掃描線仍按原有字模、逐格反白狀態檢查完整單色映射；不能整個事件免檢。
4. 模型只作用於 `AuditEvents` 的嚴格遮罩結果。`AuditStale`、`AuditExposed`、定色、指紋、影子、Shown/Pending、譯文排版及像素輸出不變。英文視圖仍等於原版。
5. 歷史資格只能使精確模型成為候選，不能使錯誤像素自動通過。還原未變暗頁面時，原有完整字模模型仍可通過。事件仍顯示與覆蓋核對保持現有 laterRanges 排除；嚴格檢查的普通模型與變暗候選維持同一個 scanGroup 像素集合，只排除透明格，不新增 laterRanges 排除。語言切換與頁面影子還原保留事件 id，資格隨日誌保留。

## 驗收

- 合成字型測試：未註記的兩條掃描線清除仍被 strict 抓到；已知完整格變暗通過；部分事件、未覆蓋的相鄰格、其他列與負／零寬不被免檢；變暗兩線中一個像素改為其他色仍失敗；未被抹掉的線加入雜色仍失敗。清除色 0 與反白色 3 都須通過；兩條掃描線各自單色但彼此不同須失敗。雜色負例必須仍通過 auditCell 的事件顯示前置判定，再要求 strict 失敗。變暗後普通反白、移列後變暗、語言重建及保存還原後保留正確範圍。重新繪字的新 id 不繼承資格；超過 MaxLog 後，淘汰事件與資格一同消失，同文同位置的新事件不繼承。
- 調整後的 `AuditEvents` 與原版狀態分開核對，不能拿稽核器自己的輸出當像素期望值。正式同一路線四語四模式各 42 點，共 672 點，完整原版狀態相同；on 與 40,000 步節奏 Layer 相同，有鉤子模式各列實際 PASS。
- 獨立核對兩次原版 `0740` 操作的逐位元組掃描線清除、四語正文全文、定色、原生及兩倍像素範圍、120 次不送鍵停留、英文與四語往返、拒絕不可選項及兩次返回清除。
- 乾淨匯出負對照只停用已知變暗資格的記錄，原版正常路線、全部譯文與像素不變；目標 strict 必須重新失敗。另由合成測試確認放寬成整個事件跳過時，雜色負例會失敗。
- 既有普通反白、清單捲動、語言切換及第二頁還原做最小充分回歸。沒有輸出程式或譯文變更時，證明兩者的影像及 Layer 雜湊不變。
