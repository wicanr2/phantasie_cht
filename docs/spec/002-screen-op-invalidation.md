# 002 畫面操作與疊字失效

狀態：DRAFT（2026-10-03）。依賴 `001`（疊字核心）。證據來源：`docs/re/005`、`006`，本輪補讀的 IDA 反組譯（`phantasi.asm`）與 `textlog -int10 -pages` 動態記錄。

## 1. 問題

原版會用文字以外的方式改畫面：反白、整頁存取與還原、視窗清除、捲動、貼圖。疊字若不跟著變動，會有三種錯：還原後英文原文露出、清除後殘字、反白後中文不反白。`xlate.Layer.Frame` 以像素指紋偵測改變（連續 3 幀不同，該格轉透明），只能事後把中文拿掉。本規格以事件把「已知的操作」精確對應到 `Layer` 動作，指紋偵測留作未知操作的後備。

## 2. 依據

| 事實 | 證據 | 等級 |
|---|---|---|
| 原版所有 BIOS 與 DOS 軟體中斷經 `int86(intno, inregs, outregs)`：映像位移 `4E60`，近呼叫，引數 `[SP+2]` 中斷號、`[SP+4]` 輸入 `union REGS` 指標、`[SP+6]` 輸出指標，欄位依序 `ax bx cx dx si di ds es` | `phantasi.asm` 的 `sub_5F60`；動態 hook 已取得 INT 10h 輸入暫存器 | 已證實 |

## 3. 掛點

所有 hook 唯讀，在映像段 `img` 上以 `OnCall` 掛入。「入口」是函式第一個指令前，「完成」是函式最後一個指令（`retn`）前；此時所有視訊寫入已完成（這些函式內沒有呼叫端程式碼，視訊寫入以外也沒有可被中途改變的狀態）。

| 名稱 | 入口 | 完成（`retn`） | 入口讀取 |
|---|---|---|---|
| int86 | `4E60` | 無（以入口當作時點） | 中斷號、`ax bx cx dx` |
| invert | `0672` | `073F` | `[SP+2]` row、`[SP+4]` col、`[SP+6]` width |
| invert2 | `0740` | `0799` | 同 invert |
| save1 | `0D30` | `0D4F` | 無 |
| save2 | `0D50` | `0D70` | 無 |
| load1 | `0CF0` | `0D0F` | 無 |
| load2 | `0D10` | `0D2F` | 無 |
| row24 | `372D` | `376D` | 無 |
| hash 來源 | 讀 `DS:5BAA`、`DS:5BAC`、`DS:5BAE` | | |

反白與整頁操作各自只有一個在途呼叫（不巢狀）。入口時把參數存起來，完成時套用。

## 4. 內容定址的頁面影子

`known`：從「`4000h` bytes 內容的 FNV-1a 64 位元雜湊」到「`Layer.Snapshot()` 位元組」的映射，容量 16 筆，滿了淘汰最久沒用到的。

| 操作 | 完成時動作 |
|---|---|
| save1、save2 | `h = hash(螢幕 B800:0000 起 4000h bytes)`（與被存入的內容相同）；`known[h] = Layer.Snapshot()` |
| load1、load2 | 入口時 `h = hash(對應緩衝區內容)`。完成時：`known[h]` 存在則 `Layer.Restore(snapshot)`，否則 `Layer.Clear(0, 0, 320, 200)`。兩者之後螢幕內容都等於緩衝區 |
| row24 | 入口時 `h_old = hash(緩衝區 1)`、`h_new = hash(緩衝區 1 把第 24 列兩段換成螢幕第 24 列後的內容)`。完成時：`known[h_old]` 存在則 `known[h_new] = (該 snapshot 去掉 Y = 192 的疊字) + (目前 Layer 中 Y = 192 的疊字)`；不存在則不登記 |
| 緩衝區 → 緩衝區（`2398`）、檔案讀入緩衝區、OV2 逐列填緩衝區 | 不處理。內容定址本身涵蓋：之後 load 時以實際內容查表，沒登記過的內容走 `Layer.Clear` |

`Layer.Restore` 需要字型表（`fonts` 參數，名稱對應語言通道字型）；Restore 失敗（資料損壞）視同找不到。

意義：影子只在「內容與某次登記時完全相同」才還原，所以不會把舊疊字貼到不同的畫面；查不到時退成「沒有中文」（顯示原文），不是殘留錯誤的中文。

## 5. 其他操作

| 操作 | 動作 |
|---|---|
| int86 `AH=00h` | 視訊模式改變：`Layer.Clear(0,0,320,200)`、清空 `known`、`palette` 回預設（§6） |
| int86 `AH=06h`，`AL=0` | 視窗清除：左上 `(CL, CH)`、右下 `(DL, DH)`（格），像素矩形 `[CL×8, CH×8, (DL+1)×8, (DH+1)×8)`，`Layer.Clear` 該矩形 |
| int86 `AH=06h`，`AL=n>0` | 視窗上捲 n 列：`Layer.Scroll(x0, y0, x1, y1, -8n)`，矩形同上 |
| int86 `AH=07h`，`AL=n>0` | 視窗下捲 n 列：`Layer.Scroll(x0, y0, x1, y1, +8n)`；`AL=0` 同清除 |
| int86 `AH=0Bh` | 記錄調色盤（§6），所有疊字改 `Pending`（重新取色） |
| invert、invert2 完成 | 與矩形 `[col×8, row×8, (col+width)×8, (row+1)×8)` 相交的疊字改 `Pending`（下一個 `Frame` 依反相後的像素重新定色與重算指紋）。部分相交（見 §8） |
| 未列出的操作（貼圖 `30AC`、`OV2` 逐格繪製、直接寫 `B800`） | 沒有事件對應；由 `Layer.Frame` 的指紋偵測處理：連續 3 幀不同的格轉透明 |

## 6. 調色盤

CGA 模式 04h 的四色由調色盤選擇與強度決定，`oracle.CGA4()` 回色號（0 至 3），不含 RGB。預設（模式設定後）是調色盤 1、高強度：色號 0 黑 `(0,0,0)`、1 青 `(85,255,255)`、2 洋紅 `(255,85,255)`、3 白 `(255,255,255)`。`AH=0Bh`：`BH=0` 設背景色（`BL` 低 4 位元，色號 0 的顏色取 16 色表）與強度，`BH=1` 選調色盤（`BL` 的 bit 0：0 為綠／紅／黃，1 為青／洋紅／白）。動態尚未量到 `AH=0Bh`，因此 `AH=0Bh` 的行為只以標準 BIOS 語意實作，實測前標為未驗證。

## 7. 與指紋偵測的分工

事件處理負責「已知操作」；`Frame` 的指紋偵測負責「事件沒有涵蓋的」與「事件之間的暫態」。`Frame` 規則不修改：Shown 疊字每格每幀比較指紋，連續 3 幀不同轉透明；錨定格全部失效或判定改寫則整筆移除。

## 8. 驗收

1. 單元測試（純 Go）：以假的記憶體讀取函式測 `known` 的登記、查找、淘汰、`row24` 合併；`AH=06h` 矩形換算；反白矩形與疊字相交判斷。期望值用字面值。
2. 同狀態收據（需原版，缺檔 SKIP）：
   - 公會選單在移動反白（`Down`）前後，被反白的項目仍是中文，且前後顏色反相；其餘項目不變。
   - 開啟視窗（查看清單）後以 `Esc` 關閉：關閉後的畫面，疊字集合等於開啟前（`Snapshot` 位元組相等）。
   - 視窗清除：視窗內舊疊字被移除，視窗外保持。
3. 負對照：關閉 `load1` 的 `known` 查找（一律 `Clear`），上列第二項收據應失敗。關閉 invert 的 `Pending`，第一項應失敗。
4. 覆蓋清單：驗收時列出每一種在途操作（int86 的 `AH`、七個畫面函式）在收據路線中被觸發的次數；次數為 0 的標「未量到」。

## 9. 未決

1. 反白的部分相交：若原版反白矩形只涵蓋某筆疊字的一部分格（例如同一行含多欄），`Pending` 重新定色會把整筆疊字當成同一顏色。動態量到前不處理，量到再補（拆筆或逐段定色）。
2. `AH=0Bh` 與 `0740`（invert2）的用途與動態行為。
3. OV2 的旗標 `DS:C5F8` 為真時，繪製進緩衝區的內容是否含 `25A5` 的文字（`25A5` 自己只寫 `B800`、`BA00`，不認緩衝區，所以預期不含）。
4. 緩衝區 → 緩衝區的複製（`2398`）在 `known` 中不需要處理，但仍要確認實際內容雜湊在複製前後相同（單元測試以假記憶體驗證，動態收據以雜湊印出）。
5. `sub_48A0` 的功能與其對疊字的影響。
