# 002 畫面操作與疊字失效

狀態：DRAFT 第二版（2026-10-03，依第一輪兩份審查修訂）。依賴 `001`（疊字核心）與 dosgolem 規格 243（CGA 圖形模式的 INT 10h 捲動、清除與調色盤）。證據來源：`docs/re/005`、`006`、`008`，`textlog -int10 -pages -ops` 動態記錄與 `cmd/overlay-prototype` 的原型截圖（開啟反白前後對照）。

## 1. 問題

原版會用文字以外的方式改畫面：反白、整頁存取與還原、視窗清除、捲動、貼圖。疊字若不跟著變動，會有三種錯：還原後英文原文露出、清除後殘字、反白後中文不反白。`xlate.Layer.Frame` 以像素指紋偵測改變（連續 3 次 `Frame` 不同，該格轉透明），只能事後把中文拿掉。本規格以事件把「已知的操作」精確對應到 `Layer` 動作，指紋偵測留作未知操作的後備。

## 2. 依據

## 3. 掛點

所有 hook 唯讀，在映像段 `img` 上以 `OnCall` 掛入；「入口」是函式第一個指令前，「完成」是 `retn` 前。每個掛點安裝前驗證簽章（入口 `55 8B EC`，完成位址 `C3`，`001` §3.1）。成對 hook 的冪等去重同 `001` §3.2（開啟旗標加 `SP`）。

| 名稱 | 入口 | 完成 | 入口讀取 |
|---|---|---|---|
| int86 | `4E60` | `4EE0` | 中斷號、`ax bx cx dx` |
| invert | `0672` | `073F` | `[SP+2]` row、`[SP+4]` col、`[SP+6]` width |
| invert2 | `0740` | `0799` | 同 invert |
| save1 | `0D30` | `0D4F` | 無 |
| copy12 | `0D50` | `0D70` | 無 |
| load1 | `0CF0` | `0D0F` | 無 |
| load2 | `0D10` | `0D2F` | 無 |
| row24 | `372D` | `376D` | 無 |
| hash 來源 | 讀 `DS:5BAA`、`DS:5BAC`、`DS:5BAE` | | |

入口時把參數存起來，**完成時套用**（只做一次）。

## 4. 內容定址的頁面影子

`known`：從「`4000h` bytes 內容的 FNV-1a 64 位元雜湊」到「`Layer.Snapshot()` 位元組」的映射，容量 16 筆，滿了淘汰最久沒用到的。

| 操作 | 動作 |
|---|---|
| save1 | 完成時 `h = hash(螢幕 B800:0000 起 4000h)`（與被存入的內容相同）；`known[h] = Layer.Snapshot()` |
| load1、load2 | 入口時 `h = hash(對應緩衝區內容)`。完成時：`known[h]` 存在則 `Layer.Restore(snapshot)`；不存在則 `Layer.Clear(0, 0, 320, 200)` 並登記 `known[h] = Layer.Snapshot()`（空層，正是該內容的正確影子，讓之後的 row24 能在其上合併）。兩者之後螢幕內容都等於緩衝區 |
| row24 | 入口時 `h_old = hash(緩衝區 1)`、`h_new = hash(緩衝區 1 把第 24 列兩段換成螢幕第 24 列後的內容)`。完成時：`known[h_old]` 存在則 `known[h_new] = (該快照去掉 Y = 192 的疊字) + (目前 Layer 中 Y = 192 的疊字)`；不存在則不登記 |
| copy12 | 不處理：複製不改內容，內容定址已涵蓋（緩衝區 2 的內容與入口時緩衝區 1 相同，`known` 已以該雜湊登記或沒有登記） |
| `2398`、檔案讀入緩衝區、OV2 逐列填緩衝區 | 不處理：內容改變，之後 load 時以實際內容查表，沒登記過的走 `Clear` 並登記空層 |

`Layer.Restore` 需要字型表（`fonts` 參數，名稱對應語言通道字型）；Restore 失敗（資料損壞、字型名稱缺）視同找不到。

設計取捨（已知）：OV2 的地圖重畫與讀檔補丁會在 save1 之後改動緩衝區 1，使之後的 load1 必然 miss 而 `Clear` 整層，連未被改動區域的疊字也一起失效。結果是「回到英文原文」，不是殘留錯誤的中文。

語言切換：依 `004` §5 重建 `known` 內每筆快照（或在無法重建時移除該筆）。

## 5. 其他操作

| 操作 | 動作 |
|---|---|
| int86 `AH=00h` | 視訊模式改變：`Layer.Clear(0,0,320,200)`、清空 `known` |
| int86 `AH=06h`，`AL=0` | 視窗清除：左上 `(CL, CH)`、右下 `(DL, DH)`（格），像素矩形 `[CL×8, CH×8, min((DL+1)×8, 320), min((DH+1)×8, 200))`，`Layer.Clear` 該矩形 |
| int86 `AH=06h`，`AL=n>0` | 視窗上捲 n 列：`Layer.Scroll(x0, y0, x1, y1, -8n)`，矩形同上 |
| int86 `AH=07h`，`AL=n>0` | 視窗下捲 n 列：`Layer.Scroll(x0, y0, x1, y1, +8n)`；`AL=0` 同清除 |
| int86 `AH=0Bh` | 所有疊字改 `Pending`（調色盤可能改變，下一次 `Frame` 重新取色）；RGB 一律由 `oracle.CGAPalette()` 取得（dosgolem 規格 243），本規格不自行追蹤色彩選擇 |
| invert 完成 | 與矩形 `[col×8, row×8, (col+width)×8, (row+1)×8)` 相交的疊字改 `Pending`（下一個 `Frame` 依反相後的像素重新定色與重算指紋）。部分相交見 §9 |
| invert2 完成 | 不動作，計入 `dim`。已知限制：原版對停用項目抹掉第 2、4 條掃描線造成的「變暗」效果在疊字下看不出來；需要時另開規格（`xlate` 遮罩能力） |
| 未列出的操作（貼圖 `30AC`、`OV1`、`OV2` 的圖形函式、直接寫 `B800`） | 沒有事件對應；由 `Layer.Frame` 的指紋偵測處理：連續 3 次 `Frame` 不同的格轉透明 |

## 6. 調色盤與 RGB

CGA 模式 04h 的四色由色彩選擇暫存器決定，`oracle.CGAPalette()`（dosgolem 規格 243）回 `[4][3]uint8`。`Layer.Frame` 的 `rgb` 引數由前端依 `CGAPalette()` 把 `CGA4()` 色號換算而得。預設（設模式後）是調色盤 1、高強度、背景黑：色號 0 黑、1 淺青 `(85,255,255)`、2 淺洋紅 `(255,85,255)`、3 白。

## 7. 與指紋偵測的分工

事件處理負責「已知操作」；`Frame` 的指紋偵測負責「事件沒有涵蓋的」與「事件之間的暫態」。`Frame` 規則不修改：Shown 疊字每格每次 `Frame` 比較指紋，連續 3 次不同轉透明；錨定格全部失效或判定改寫則整筆移除。

反白完成之前的暫態：invert 入口到完成之間若有一次 `Frame`，該次比較只會讓 `misses` 加 1（小於 3），完成後的 `Pending` 重取色會歸零。

## 8. 驗收

1. 單元測試（純 Go，以假的記憶體讀取函式，期望值字面值）：`known` 的登記、查找、淘汰、`row24` 合併；**load miss 後登記空層，接著 row24 能合併出含城名疊字的快照**；`AH=06h`／`07h` 矩形換算與夾邊；反白矩形與疊字相交判斷；「反白、捲動、反白、繪字」序列；冪等去重（入口重入忽略）。
2. 同狀態收據（需原版，缺檔 SKIP）：
   - 公會選單在移動反白（`Down`）前後，被反白的項目仍是中文，且前後顏色反相；其餘項目不變。
   - 開啟視窗（查看清單）後以 `Esc` 關閉：關閉後的 `Layer` 與「沒有開過視窗的原生路線到達同一個 vram 雜湊時」所建出的疊字集合（`Key` 以外的位置與 `Text`）相同。比對的對象是獨立路線，不是還原前後自己的快照。
   - 視窗清除：視窗內舊疊字被移除，視窗外保持（此項需 dosgolem 規格 243 已實作）。
3. 負對照：關閉 `load1` 的 `known` 查找（一律 `Clear`），上列第二項收據應失敗。關閉 invert 的 `Pending`，第一項應失敗。
4. 覆蓋清單：驗收時列出每一種在途操作（int86 的 `AH`、七個畫面函式）在收據路線中被觸發的次數；次數為 0 的標「未量到」。目前動態未量到：`load2`、`copy12`、`invert2`、`AH=0Bh`、`AH=07h`。
5. 擷取順序：收據擷取畫面前先呼叫一次 `Frame`（`Add`、`Clear`、反白、`AH=0Bh` 都會讓疊字進入 `Pending`，`Frame` 前不顯示）。

## 9. 未決

1. 反白的部分相交：若原版反白矩形只涵蓋某筆疊字的一部分格，`Pending` 重新定色會把整筆疊字當成同一顏色。動態量到前不處理，量到再補（拆筆或逐段定色）。
2. `AH=0Bh` 的動態行為與 `BL=0`、`1` 兩種的實際畫面。
3. 停用項目變暗（`invert2`）的重現方式。
4. 清單捲動（`sub_249C` 的反白、`AH=06h AL=1`、反白、繪新列）的動態收據：靜態已確認這個序列，動態未走到。
